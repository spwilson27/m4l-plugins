# AGENTS.md — Technical Guide & Rules for AI Contributors

This repository contains Max for Live (`.amxd`) devices for **Ableton Live 12 Suite (Max 9.1+)**.

---

## 1. Core Project Rules

1. **Directory Structure**:
   - **`devices/`** — Output directory for all compiled `.amxd` devices (e.g., `devices/Better Shaper.amxd`). Never leave generated `.amxd` files in the project root.
   - **`src/`** — JavaScript (`v8ui` / `v8.codebox`) and DSP source files (e.g., `src/mseg_editor.js`).
   - **`scripts/`** — Build and visual preview scripts (`scripts/build_shaper.py`, `scripts/render_preview.py`).
   - **`tests/`** — Automated verification and unit/interaction test suites (e.g., `tests/test_shaper.js`).
   - **`previews/`** — Rendered 2x Retina plugin screenshots named per plugin (e.g., `previews/better_shaper.png`).
2. **Never Hand-Edit `.amxd` Binary Files**:
   - `.amxd` files in `devices/` are build artifacts generated by `scripts/`. Always edit `src/` and `scripts/`, then run the build script to regenerate `devices/*.amxd`.
3. **Mandatory Build, Test & Visual Screenshot Inspection Gate**:
   - Every change to `src/` or `scripts/` **must** be followed by running the build, test, and preview pipeline for that plugin:
     ```bash
     # Better Shaper
     python3 scripts/build_shaper.py && node tests/test_shaper.js && python3 scripts/render_preview.py "devices/Better Shaper.amxd"

     # XO Sample Map
     python3 scripts/build_xo_map.py && node tests/test_xo_map.js && python3 scripts/render_preview.py "devices/XO Sample Map.amxd"

     # Tiny Space
     python3 scripts/build_tinyspace.py && node tests/test_tinyspace.js && python3 scripts/render_preview.py "devices/Tiny Space.amxd"

     # Sand
     python3 scripts/build_sand.py && node tests/test_sand.js && python3 scripts/render_preview.py "devices/Sand.amxd"

     # Reciprocator
     python3 scripts/build_reciprocator.py && node tests/test_reciprocator.js && python3 scripts/render_preview.py "devices/Reciprocator.amxd"

     # Percipitator
     python3 scripts/build_percipitator.py && node tests/test_percipitator.js && python3 scripts/render_preview.py "devices/Percipitator.amxd"

     # Degrade
     python3 scripts/build_degrade.py && node tests/test_degrade.js && python3 scripts/render_preview.py "devices/Degrade.amxd"

     # Multiband Split
     python3 scripts/build_mbsplit.py && node tests/test_mbsplit.js && python3 scripts/render_preview.py "devices/Multiband Split.amxd"

     # Cepstra
     python3 scripts/build_cepstra.py && node tests/test_cepstra.js && python3 scripts/render_preview.py "devices/Cepstra.amxd"

     # Better Sampler (one build writes all 4 .amxd variants)
     python3 scripts/build_sampler.py && node tests/test_sampler.js && for v in "Better Sampler Compact" "Better Sampler Standard" "Better Sampler Expanded" "Better Sampler"; do python3 scripts/render_preview.py "devices/$v.amxd"; done

     # Envelope Trigger
     python3 scripts/build_envtrig.py && node tests/test_envtrig.js && python3 scripts/run_envtrig_ui_tests.py && python3 scripts/render_preview.py "devices/Envelope Trigger.amxd"
     ```
   - **Visual Screenshot Inspection**: After generating `previews/<plugin_slug>.png`, agents **must** view the image in `previews/` using the `read` tool and visually verify that:
     - No text labels or toolbar buttons are truncated, squished, or overlapping.
     - Compact toolbar buttons use clean geometric vector icons (`mgraphics` paths) rather than multi-character text strings when cell width is `< 28px`, displaying full titles in the HUD tooltip on hover.
     - All `live.*` widgets, panels, and `v8ui` canvases have balanced padding and alignment.
   - Any visual defect identified in the screenshot must be fixed and re-verified before finishing.
4. **Presentation Mode Layout & Z-Order Rules**:
   - Max for Live devices must maintain a fixed presentation height of **`169.0` px** (`openrect: [0.0, 0.0, <devicewidth>, 169.0]`, `openinpresentation: 1`).
   - **Never overlap `live.*` interactive widgets (`live.numbox`, `live.text`, `live.dial`, `live.tab`) with a `v8ui` / `jsui` canvas in Presentation Mode.** Max's `v8ui` captures all mouse clicks over its `presentation_rect`. Keep `live.*` widgets in non-overlapping header/side regions (verified automatically by `tests/test_shaper.js`).
   - **Exception (ignoreclick face)**: a `live.*` widget MAY overlap a `v8ui` only when that `v8ui` has `"ignoreclick": 1` (it only draws) **and** the `live.*` widget sits in front of it in z-order (later in `boxes`). This is how a custom-drawn control stays automatable / mappable (right-click > Show Automation, Map to Macro, MIDI/Key map): the real `live.*` parameter object sits over the drawing as a fully transparent widget (every colour attribute alpha `0`, `showname 0`, `shownumber 0`, no text), and the `v8ui` redraws from the parameter via `prepend set_<x>`. Any interactive `v8ui` (no `ignoreclick`) must still have zero `live.*` overlap. Enforced by `tests/test_cepstra.js`.
5. **Instance Isolation (`#0-` Naming)**:
   - Any `buffer~`, `send`, or `receive` that belongs to a single device instance **must** be prefixed with `#0-` (e.g., `buffer~ #0-mseg`, `index~ #0-mseg`) so multiple instances of the device across an Ableton Live Set never collide.
6. **Backward-Compatible State Serialization (`getvalueof` / `setvalueof`)**:
   - `v8ui` state is saved in Ableton Live Sets (`.als`) and presets (`.adv`) via blob parameter `ShapeData` (`parameter_type: 3`).
   - Always version the array returned by `getvalueof()` (first element = version integer) and keep fallback parsing for earlier versions inside `setvalueof()` so existing Live Sets never lose user curves.
7. **Undo Stack Discipline**:
   - Any user interaction that mutates MSEG points, segment curves, S-curve flags, or loop markers must call `pushUndoState()` once at the start of the gesture (`onclick` or `ondblclick`)—never on every `ondrag` frame—and call `notifyclients()` on gesture completion.
8. **`gen.codebox~`, `v8ui` Pixel Coordinates, Background Panels & Real Max Audio Verification**:
   - **`v8ui` Pixel Coordinates**: Always call `mgraphics.init(); mgraphics.relative_coords = 0; mgraphics.autofill = 0;` at the top of every `v8ui` script. Without `relative_coords = 0`, Max 9 clips pixel drawing to `0..1` and renders a blank panel in Live.
   - **Background Panel Z-Order**: All decorative `panel` boxes must appear **at the end** of the `boxes` list and include `"background": 1`, or they will cover interactive controls in Ableton Live.
  - **Integer Parameter Ranges `> 255` in Live**: Ableton Live's native `Int` parameter type (`"parameter_type": 1`) is an 8-bit integer limited to `0..255`. Any `live.numbox` or `live.dial` whose integer range exceeds `255` (such as `Seed` `0..1000`) **must** set `"parameter_type": 0` (`Float`) and `"parameter_unitstyle": 0` (`Int`).
   - **`live.numbox` Slider Fill Opacity & Bipolar Appearance (`appearance: 2` vs `3`)**:
     - `appearance: 2` (`Slider`) fills from the left edge; `appearance: 3` (`Bipolar`) fills outward from the center midpoint (`0` or `50%`).
     - Ableton Live ignores alpha in `activeslidercolor` and paints the slider fill opaque. Always pre-blend `activeslidercolor` (`38%` accent color + `62%` dark `activebgcolor`) so value text in `textcolor` remains high-contrast and legible over the fill bar inside Ableton Live.
   - **GenExpr Ordering & Lexer Rules**:
     - Every helper function must appear **before** all `Buffer`, `Param`, `History`, and `Delay` declarations, which in turn must appear **before** all expression statements.
     - **Never name identifiers `e0`–`e9`** (or `e` followed by digits): GenExpr's lexer parses `e0` as Euler's constant `e` (`2.71828...`) rather than an identifier.
     - Use `Delay d(size); d.write(x); y = d.read(samps, interp="linear");` instead of `delay()`.
     - Bind `Buffer varName("extName");` on `loadbang` using the **GenExpr variable name with no `set` prefix** (e.g., `scope #0-recipscope`).
   - **Real Max Audio Test Harness**: Every DSP device must have an automated Max audio test runner (`scripts/run_<device>_audio_tests.py`) that clears `~/Library/Application Support/Cycling '74/Max 9/Crash Recovery`, records into a 2-channel `buffer~ rec <durationMs> 2`, waits until the probe output file size stabilizes before reading, and verifies audio behavior and live UI telemetry buffer updates.

## 2. `.amxd` Binary Format Reference

An unencrypted Max for Live `.amxd` file consists of a 32-byte binary header followed by UTF-8 JSON patcher data:
- Bytes `0..7`: `b"ampf\x04\x00\x00\x00"`
- Bytes `8..11`: Device type 4CC:
  - `b"aaaa"` (`amxdtype: 1633771873` / `0x61616161`) — Max Audio Effect (`plugin~` / `plugout~`)
  - `b"mmmm"` (`amxdtype: 1835887981` / `0x6d6d6d6d`) — Max MIDI Effect (`midiin` / `midiout`)
  - `b"iiii"` (`amxdtype: 1768515945` / `0x69696969`) — Max Instrument
- Bytes `12..23`: `b"meta\x04\x00\x00\x00\x00\x00\x00\x00"`
- Bytes `24..27`: `b"ptch"`
- Bytes `28..31`: `uint32_le` length of the following JSON byte payload.
- Bytes `32..end`: UTF-8 encoded patcher JSON ending with `\n`.

### `v8ui` + Audio-Rate `buffer~` Integration
- `obj-mseg` (`maxclass: "v8ui"`) embeds the ES6+ script inline via `"textfile": { "text": ..., "filename": "none", "flags": 0, "embed": 1, "autowatch": 1 }`.
- `obj-buf` (`buffer~ #0-mseg @samps 4096`) holds the 4096-sample lookup table. On startup, `loadmess setbuffer #0-mseg` passes the unique `#0-mseg` buffer name to `v8ui`, which writes all 4096 samples via `new Buffer(bufName).poke(1, 0, samples)` whenever the curve changes.
- `v8ui` Outlet 0 emits `["loop", loopStart, loopSpan]` to window the MSP `phasor~` phase into `[loopStart, loopStart + loopSpan]`, and `["syncphase", phase]` to align `phasor~` with Ableton Live's 1-PPQ arrangement timeline position (`plugsync~` outlet 6) in Sync mode.
- `v8ui` Outlet 1 emits the LFO frequency in Hz to `phasor~` (automatically scaled by `1 / loopSpan` when a loop sub-region is active so tempo-synced subdivisions keep constant musical speed).

## 5. Architecture of `devices/Tiny Space.amxd`

### Presentation Layout (`292 x 169` px — `devices/Tiny Space.amxd`)
- **Left Column (`x = 6..62`)**: `PreDly` numbox + `HP` & `LP` dials.
- **Center Column (`x = 66..226`)**: Top header (`tinyspace`, `Seed` 0–1000 numbox using `parameter_type: 0, parameter_unitstyle: 0`, and `Character` 8-model dropdown `live.menu`: `COMB`, `HYBRID`, `ROOM`, `PLATE`, `TANK`, `BOX`, `SPRING`, `BOUNCE`), center `152 x 74` `v8ui` overlaid L+R string screen (`obj-viz`), and bottom 3 dials (`Size`, `Fbk`, `XFeed`).
- **Right Column (`x = 230..286`)**: `Damp` & `Mod` numboxes + `Width` & `Mix` dials.

### Gen core (`gen.codebox~`, hidden)
- `src/tinyspace_core.genexpr` — FDN: predelay → HP/LP → seeded allpasses → 20 delay lines (10 L / 10 R) with linear interpolation, per-line damping, soft clip, an orthogonal per-model mix (identity, sum-preserving rotation, Householder, Householder-cycle, sign-flipping ring, Householder wall-swap, spring lattice, or reversal), a unitary crossfeed rotation → width (M/S) → equal-power dry/wet.
- Audio is `in1`/`in2`. Knobs are Gen `Param`s (`size`, `damp`, `width`, `wet`, `fbk`, `predly`, `modamt`, `xfeed`, `hp`, `lp`, `duck`), sent with `prepend`.
- `Buffer cfg("tsconfig")` reads the 70-float seed config. `Buffer meters("tsmeters")` gets one envelope per line every 32 samples. Loadbang binds them with `cfg #0-tsconfig, meters #0-tsmeters` (the GenExpr variable, with no `set` prefix). An unbound buffer peeks as zeros, every delay line stays off, and Mix at 100% is silent.
- Percent knobs are scaled by `/ 100.` before they hit gen. Feedback uses a delay-style RT60 curve (`feedbackRt60`): about 0.7 s at 50%, about 2.7 s at 75%, and about 27.5 s at 100% (60 dB down). Every room model shares that tail because the mix is orthogonal and the all-ones mode has eigenvalue magnitude 1. The per-loop coefficient is higher on short lines so a small Size rings about as long as a long one, and it stays under 1. Feedback at 0 writes no recirculation. Delay taps are whole samples, and Damp at 0 is a bypass (`pole = 0`), so short combs stay metallic. Above 0, Damp is a per-pass one-pole on every delay tap, including the first reflection: about 5 kHz at 20%, about 1.8 kHz at 50%, and a few hundred hertz at 100% on an 8 ms line. Short lines use a higher cutoff so a 1 ms comb is not filtered much harder than a long room line. Every room model shares that filter. Crossfeed is a rotation (`xfeed * pi/2`), so a partial XFeed does not burn energy.

### Seed → config
- `src/tinyspace_config.js` (mulberry32, `Seed` 0–1000) is prepended into the v8ui script and required by `tests/test_tinyspace.js`. Lower seeds use fewer active delay lines (`4` at Seed `0`), scaling monotonically up to the `20`-line cap (`10 L + 10 R`) as Seed approaches `1000`.
- The `Seed` numbox calls `set_seed`. The UI pokes `buffer~ #0-tsconfig`. User knobs are not rewritten.
- A later seed change bangs a `line` that ramps Gen `duck` from 0 to 1 over 160 ms so the old tail does not thump.
- The seed is a Live parameter, so sets and presets recall it without a separate blob.

```bash

```
Audio checks (real Max render): `python3 scripts/run_tinyspace_audio_tests.py`

## 6. Architecture of `devices/Sand.amxd`

### Presentation Layout (`296 x 169` px — Compact Single-Column Edition)

  - Graphic HUD Control Strip (`y = 26..42`): Automatable `Amount` value box (`0..140 dB`), `Freq` value box (`20 Hz..18 kHz`), and `Out` selection slider/box (`Off` / `Hard` / `Limit`, `appearance: 1`).
  - Audio-Reactive XY Scope (`obj-viz`, `v8ui`, `x = 10, y = 46, w = 192, h = 114`): Draws stereo wet grit trace, dry input ghost silhouette, audio-reactive sand grain particles, compander transfer curve inset, and dual `G` (pre-mix wet grit) / `O` (post-mix output) meters. Dragging vertically adjusts `Amount`; dragging horizontally adjusts `Freq` (synced bidirectionally with `obj-amount` and `obj-freq`).
- **Right Panel (`x = 210..290` — Single Visual Column)**:
  - `Filt` (`highcut.svg` / `bandpass.svg` / `lowcut.svg` filter curve icons, `usepicture: 1`) and `Place` (`Pre` / `Diff` / `Post`) selector rows at the top.
  - `Soft` (`%`) and `Debrick` (`%`) horizontal value bars (`live.numbox`, `appearance: 2`) in the middle, with the `Mix` (`%`) radial dial at the bottom.

### Gen core (`gen.codebox~`, hidden)
- `src/sand_core.genexpr` — per channel: optional pre-filter, derivative order or a leaky integrator, optional mid filter, 1–4 compander stages, optional post filter, equal-power dry/wet mix, then the output stage.
- Each differentiator peaks at unity at Nyquist and is clipped, so order 15 cannot amplify rounding error into a square wave. Amount 0 is unity gain on order 0. Amount 140 dB is about 10^7 of extra gain on quiet samples, then a soft or hard knee.
- `Out` is bypass (`Off`), hard clip at ±1 (`Hard`), or a fast limiter with a ceiling near −1 dB (`Limit`). The limiter history always runs.
- `Buffer wave("sandwave")` gets stereo output, dry input, wet grit, and peak envelopes every 32 samples. Loadbang binds it with `wave #0-sandwave`. Audio does not depend on the buffer.

### Nested Rack ("Chain within a Chain") Scoping, Same-Chain (`Cmd+D`) Isolation & Cross-Instance Sync
- `parseRackContextFromPath(lomPath)` in `src/mbsplit_config.js` inspects `LiveAPI("this_device").unquotedpath` and extracts the **immediate enclosing `RackDevice` LOM path** (`parentRackPath`), **immediate enclosing `chains <N>` index** (`chainIndex`), and **device index within that chain** (`devices <D>` -> `deviceIndex`).
- **Nested Rack Scoping**: In `Auto` link mode, instances inside an outer Audio Effect Rack link exclusively with siblings in that outer rack and auto-create `1..4` bands matching the detected instances (`Chain 1..N -> Band 1..N`), while instances inside a nested sub-rack ("a chain within a chain") link exclusively with siblings inside that nested sub-rack.
- **Same-Chain (`Cmd+D`) Left-Most vs. Right-Hand Isolation**:
  - Within any chain `(parentRackPath, chainIndex)`, `isLeftMostInOwnChain()` and `getActiveGroupKey()` in `src/mbsplit_ui.js` compare alive splitters by `(deviceIndex, order, id)`.
  - Only the **left-most** splitter in each chain (`isLeftMostInOwnChain() === true`, e.g. `chains 0 devices 0`) joins `"rack_group::" + parentRackPath`.
  - Any splitter to the **right** in the same chain (`isLeftMostInOwnChain() === false`, such as a `Cmd+D` duplicate at `chains 0 devices 1` before it is grouped into a sub-rack) receives `"rack_group::isolated::" + INSTANCE_ID`, keeping it in its own empty `1`-band chain (`1:FULL`) with independent crossovers.
  - Reordering a right-hand splitter to `devices 0` or deleting the left-most splitter automatically promotes the new left-most splitter into `"rack_group::" + parentRackPath` and syncs the rack's `F1` / `F2` / `F3` / `Slope`.
- **Cross-Instance `LiveAPI("this_device")` Thread Safety & Allocation Reuse**:
  - In Max for Live (`v8ui`), calling `new LiveAPI(..., "this_device")` inside a cross-instance `Global` callback resolves `"this_device"` to the *caller's* patcher rather than the callee's patcher. Each instance therefore caches a single `selfLiveApi` bound on its own thread (`isOwnThread !== false`) and reuses `selfLiveApi.unquotedpath` during liveness and topology checks, preventing cross-instance path clobbering and main-thread `LiveAPI` allocation floods.
- Cross-instance synchronization uses `Global("mbsplit_shared_bus")` to link `F1` / `F2` / `F3`, `Slope`, `Phase Mode`, and auto-detected `NumBands` while keeping `BandMode`, `CustomMask`, and `Gain` (`-inf..+18 dB`) independent per chain.
- `SplitStateData` blob is version 3: `[3, f1, f2, f3, numBands, slope, bandMode, customMask, linkGroup, gainDb, showLinkStatus, phaseMode]` (v1 / v2 still load; they leave the phase mode alone).

### Dynamic Phase (`Phase Mode` = `DYN`, gen `dynphase 1`)
- **F1** stays the minimum-phase Linkwitz-Riley split (selected `Slope`). **F2 / F3** become complementary linear-phase FIR splits of the F1 high band: Kaiser (`beta 6`) windowed-sinc lowpass, symmetric half-length `D` taps, DC-normalized; `band2 = LP2 * hi`, `band3 = LP3 * hi - LP2 * hi`, `band4 = delay_D(hi) - LP3 * hi`, `band1 = delay_D(lo)` (`delay_D(x)` with 1 band). The sum is exactly the F1 allpass delayed by `D`, whatever the kernels are, so kernel redesigns (every 32 samples while F2 / F3 move) never break the flat sum.
- `D = 128 * round(sr / 48000)` clamped `128..512` (`128` at 44.1 / 48 kHz, about 2.7 ms; `256` at 96 kHz). F2 / F3 transition: about `sr / D` (375 Hz at 48 kHz) either side of the crossover, from -0.7 dB to below -60 dB, so slopes get gentle below about 300 Hz. That is why F1 stays IIR.
- Switching modes fades out for 4 ms, swaps, then fades in for 4 ms. The rings always run, so the new mode starts with valid history.
- **Latency reporting**: gen publishes `D` at `scope[26]` and the active mode at `scope[27]`. The v8ui calls `this.patcher.setattr("latency", phaseMode ? D : 0)` (`updateDeviceLatency()`). Live re-reads this at runtime: verified through the MCP bridge, where `latency_in_samples` followed the attribute immediately. Every linked instance carries the same phase mode, so all Rack chains report the same latency.
- JS mirror in `src/mbsplit_config.js`: `firLatencyForSampleRate`, `designFirHalfKernel`, `evalFirHalfKernel`, `computeFirLowpassMag` (raised-cosine display approximation, within 0.1 of the real kernel), and `createReferenceSplitterDsp(sr).processSampleDynamic`.

### Gen core (`gen.codebox~`, hidden)
- `src/mbsplit_core.genexpr` — Phase-compensated stereo Linkwitz-Riley crossover tree (`12 dB/oct` LR2, `24 dB/oct` LR4, `48 dB/oct` LR8) supporting `1..4` bands with matching allpass phase-compensation stages (`ap2_b1`, `ap3_b1`, `ap3_b2`) so parallel chains sum to a flat `0.000 dB` allpass unity response across all crossover frequencies, plus `-70..+18 dB` (`-inf..+18 dB`) output volume.

- `src/cepstra_core.genexpr` — true cepstral formant shifter: STFT overlap-add with Hann analysis and Hann synthesis windows at 75% overlap (hop `N/4`, normalized by `1 / (N * 1.5)`), FFT size `N = 1024 * 2^quality` (`1024` / `2048` / `4096`), own radix-2 FFT written as GenExpr helper functions over `Data` arrays sized for `4096`, `float64` precision.
  - **Mid/Side packing**: `M = (L + R) / 2`, `S = (L - R) / 2`. `M + jS` share one complex FFT. Because both log-spectra and both cepstra are real and symmetric, the same packing carries them through all four FFTs per hop (forward FFT, cepstrum IFFT, envelope FFT, synthesis IFFT).
  - **Per-frame pipeline** (`job_*` functions): `logmag = log(|X| + 1e-9)` -> cepstrum `c = IFFT(logmag)` -> lifter (`|n| < L`, half-Hann taper over `clip(L / 4, 2, 6)` bins) -> envelope `E = FFT(formant cepstrum)` -> fine structure `H = logmag - E` -> shifted envelope `E'[k] = E[k / 2^(st/12)]` (linear interpolation, `midshift` for Mid, `sideshift` for Side) -> harmonic gate (`gate_h`: soft-knee threshold from `0` (off) to `+30 dB` above the envelope, removing the noise between partials while partials keep the envelope) -> output magnitude `exp(clip(fmtlevel * E' + harmlevel * H_gated, -21, 12))` with the original phase -> IFFT -> synthesis window -> overlap-add. Neutral settings (`shift 0`, levels `100%`, gate `0`) are an exact magnitude identity.
  - **Cutoff modes** (`resmode`): `0` Manual (`res` -> `0.3 ms .. 15 ms`, logarithmic, clamped `< N/2`); `1` Auto (largest local maximum of the Mid cepstrum in `1/1000 s .. 1/60 s` with parabolic refinement and a `0.06` voicing threshold; `L = k * period`, `k = 0.3 + 0.7 * res`, held when unvoiced); `2` MIDI (`midinote` Param, `period = sr / mtof(note)`, same `k`, last value kept with no note). `L` is smoothed between frames (`0.4` per frame).
  - **Time-sliced work**: each frame is `4 * log2(N) + 10` jobs (one FFT pass or one slice of an O(N) loop each), spread across the first `N/8` samples of the hop, so no single sample runs more than one FFT pass. Latency is therefore `N + N/8` samples (`2304` at `2k`); the dry path is delayed by the same amount (`Data` ring) and Mix is equal-power.
  - **Quality switch**: changing `quality` aborts the in-flight frame, clears the overlap-add rings and mutes the output for `N + N/8 + 3 * hop + 256` samples with a 256-sample fade-in (brief mute, no crash).
  - **Silence sleep**: input below `-100 dB` (`0.00001`) for a whole frame (`quietCount >= N`) skips all FFT work (lossless: such a frame's output is zero); outputs go through `fixdenorm` / `fixnan`.
- `Buffer scope("cepscope")` (`272` samples), bound on `loadbang` via `scope #0-cepscope`: `0..191` the **signed** Mid cepstrum `c[n]` on 192 **linear** quefrency columns (`n = 0 .. 20 ms`, `qmax = 0.02 * samplerate`; each column keeps the bin with the largest `|c|` and its sign; `9999` = column at or beyond `N/2`), `256` current `L` in samples, `257` f0 estimate (Hz), `258` input level, `259` frame counter, `260` `N`, `261` voiced flag, `262` `resmode`. Written once per frame.
- MIDI: `midiin` -> `midiparse` -> `unpack 0 0` -> `> 0` (velocity) opens a `gate` so only note-ons pass -> `prepend midinote` -> gen (and `prepend midi_note` -> `v8ui`). Note-offs close the gate, so the last note is kept.

### MIDI out from an audio effect (MidiRouter technique)
- **How it routes:** an Audio Effect sends MIDI to any track through a plain `midiout`, which goes to the device's LOM DeviceIO `this_device midi_outputs 0`. - **Reading values in v8:** `get()` returns `["{json}"]`. Observer callbacks pass `[property, <Max Dict>]`, where the Dict is a handle like `{name: "u0950..."}` that must be read with `.stringify()`. `lomValue()` in `src/envtrig_config.js` handles every shape. - **Destination track:** it must be monitoring (`In`, or `Auto` while armed) for its instrument to play.
- **Note path:** gen gate → `edge~` → `t b b`. The right outlet samples the held velocity with `snapshot~` into `makenote`'s velocity inlet; the left outlet sends `i <note>` to `makenote`'s pitch inlet. Then `pack 0 0` → `midiformat` (channel inlet 6) → `midiout`.
- **Timing:** notes are scheduler-timed (one audio vector of jitter), plus the 2.5 ms velocity capture.

### Gen core (`gen.codebox~`, hidden, 4 outlets)
- `src/envtrig_core.genexpr` — single band on the mono sum. Audio passes through untouched (`out1`/`out2`).
- **Envelopes:** a fast envelope (instant attack, 15 ms release) and a slow 60 ms baseline.
- **Onset:** fires when fast > `thr` and fast > slow × `(1 − sens) × 12 dB`, while armed and outside the `holdms` lockout.
- **Velocity:** a 2.5 ms capture of the peak, mapped from threshold..0 dBFS to `velmin..velmax`.
- **Gate:** high for `holdms / 2`, so `edge~` sees it at any vector size.
- **Re-arm:** below 70 % of the threshold, or back near the baseline.
- **Outlets:** `out3` gate, `out4` held velocity.
- **Naming:** never name a Param `hold`; with that name the lockout and gate outputs silently stopped working.
- **Telemetry:** `Buffer scope("trigscope")` (`buffer~ #0-trigscope @samps 800`, bound via `scope #0-trigscope`).
  - Written every 64 samples:
    - `0` fast env
    - `1` slow env
    - `2` fire counter
    - `3` roll
    - `4` input peak
    - `5` last velocity
  - Oscilloscope ring, one block per 32 samples:
    - `6` write head (`0..255`)
    - `32 + 3 × block` holds mono min, max, and an onset flag
    - The onset flag is set at the onset, not at the end of the velocity capture, so ticks line up with attacks.
  - Pokes stop once the device has been silent for a few windows.

## 14. Architecture of `devices/Better Sampler*.amxd` (State)

- **State**: `SamplerStateData` (blob, `parameter_type: 3`) is saved with the Set/preset by `getvalueof()` in `src/sampler_ui.js`. **Version 2** = the v1 fields (mode, start/end, loop, xfade, play pos, bottom tab, slice count + slice markers ×10000) followed by the **dropped sample file path** as the last element. `setvalueof()` still parses v1 (no path, no load).
