# AGENTS.md — Technical Guide & Rules for AI Contributors

This repository contains Max for Live (`.amxd`) devices for **Ableton Live 12 Suite (Max 9.1+)**.

---

## 1. Core Project Rules

1. **Directory Structure**:
   - **`devices/`** — Output directory for all compiled `.amxd` devices (e.g., `devices/Better Shaper.amxd`). Never leave generated `.amxd` files in the project root.
   - **`src/`** — JavaScript (`v8ui` / `v8.codebox`) and DSP source files (e.g., `src/mseg_editor.js`).
   - **`scripts/`** — Build and visual preview scripts (`scripts/build_shaper.py`, `scripts/render_preview.py`).
   - **`tests/`** — Automated verification and unit/interaction test suites (e.g., `tests/test_shaper.js`).
   - **`previews/`** — Rendered 2x Retina plugin screenshots named per plugin (e.g., `previews/better_shaper.png`).
2. **Never Hand-Edit `.amxd` Binary Files**:
   - `.amxd` files in `devices/` are build artifacts generated by `scripts/`. Always edit `src/` and `scripts/`, then run the build script to regenerate `devices/*.amxd`.
3. **Mandatory Build, Test & Visual Screenshot Inspection Gate**:

   - **Visual Screenshot Inspection**: After generating `previews/<plugin_slug>.png`, agents **must** view the image in `previews/` using the `read` tool and visually verify that:
     - No text labels or toolbar buttons are truncated, squished, or overlapping.
     - Compact toolbar buttons use clean geometric vector icons (`mgraphics` paths) rather than multi-character text strings when cell width is `< 28px`, displaying full titles in the HUD tooltip on hover.
     - All `live.*` widgets, panels, and `v8ui` canvases have balanced padding and alignment.
   - Any visual defect identified in the screenshot must be fixed and re-verified before finishing.
4. **Presentation Mode Layout & Z-Order Rules**:
   - Max for Live devices must maintain a fixed presentation height of **`169.0` px** (`openrect: [0.0, 0.0, <devicewidth>, 169.0]`, `openinpresentation: 1`).
   - **Never overlap `live.*` interactive widgets (`live.numbox`, `live.text`, `live.dial`, `live.tab`) with a `v8ui` / `jsui` canvas in Presentation Mode.** Max's `v8ui` captures all mouse clicks over its `presentation_rect`. Keep `live.*` widgets in non-overlapping header/side regions (verified automatically by `tests/test_shaper.js`).
   - **Exception (ignoreclick face)**: a `live.*` widget MAY overlap a `v8ui` only when that `v8ui` has `"ignoreclick": 1` (it only draws) **and** the `live.*` widget sits in front of it in z-order (later in `boxes`). This is how a custom-drawn control stays automatable / mappable (right-click > Show Automation, Map to Macro, MIDI/Key map): the real `live.*` parameter object sits over the drawing as a fully transparent widget (every colour attribute alpha `0`, `showname 0`, `shownumber 0`, no text), and the `v8ui` redraws from the parameter via `prepend set_<x>`. Any interactive `v8ui` (no `ignoreclick`) must still have zero `live.*` overlap. Enforced by `tests/test_cepstra.js`.
5. **Instance Isolation (`#0-` Naming)**:
   - Any `buffer~`, `send`, or `receive` that belongs to a single device instance **must** be prefixed with `#0-` (e.g., `buffer~ #0-mseg`, `index~ #0-mseg`) so multiple instances of the device across an Ableton Live Set never collide.
6. **Backward-Compatible State Serialization (`getvalueof` / `setvalueof`)**:
   - `v8ui` state is saved in Ableton Live Sets (`.als`) and presets (`.adv`) via blob parameter `ShapeData` (`parameter_type: 3`).
   - Always version the array returned by `getvalueof()` (first element = version integer) and keep fallback parsing for earlier versions inside `setvalueof()` so existing Live Sets never lose user curves.
7. **Undo Stack Discipline**:
   - Any user interaction that mutates MSEG points, segment curves, S-curve flags, or loop markers must call `pushUndoState()` once at the start of the gesture (`onclick` or `ondblclick`)—never on every `ondrag` frame—and call `notifyclients()` on gesture completion.
8. **`gen.codebox~`, `v8ui` Pixel Coordinates, Background Panels & Real Max Audio Verification**:
   - **`v8ui` Pixel Coordinates**: Always call `mgraphics.init(); mgraphics.relative_coords = 0; mgraphics.autofill = 0;` at the top of every `v8ui` script. Without `relative_coords = 0`, Max 9 clips pixel drawing to `0..1` and renders a blank panel in Live.
   - **Background Panel Z-Order**: All decorative `panel` boxes must appear **at the end** of the `boxes` list and include `"background": 1`, or they will cover interactive controls in Ableton Live.
  - **Integer Parameter Ranges `> 255` in Live**: Ableton Live's native `Int` parameter type (`"parameter_type": 1`) is an 8-bit integer limited to `0..255`. Any `live.numbox` or `live.dial` whose integer range exceeds `255` (such as `Seed` `0..1000`) **must** set `"parameter_type": 0` (`Float`) and `"parameter_unitstyle": 0` (`Int`).
   - **`live.numbox` Slider Fill Opacity & Bipolar Appearance (`appearance: 2` vs `3`)**:
     - `appearance: 2` (`Slider`) fills from the left edge; `appearance: 3` (`Bipolar`) fills outward from the center midpoint (`0` or `50%`).
     - Ableton Live ignores alpha in `activeslidercolor` and paints the slider fill opaque. Always pre-blend `activeslidercolor` (`38%` accent color + `62%` dark `activebgcolor`) so value text in `textcolor` remains high-contrast and legible over the fill bar inside Ableton Live.
   - **GenExpr Ordering & Lexer Rules**:
     - Every helper function must appear **before** all `Buffer`, `Param`, `History`, and `Delay` declarations, which in turn must appear **before** all expression statements.
     - **Never name identifiers `e0`–`e9`** (or `e` followed by digits): GenExpr's lexer parses `e0` as Euler's constant `e` (`2.71828...`) rather than an identifier.
     - Use `Delay d(size); d.write(x); y = d.read(samps, interp="linear");` instead of `delay()`.
     - **No early `return` inside an `if` / loop block.** Measured in Cepstra (Max 9, `gen.codebox~`): statements after a `return` nested in a block still execute, including `poke` / `History` side effects, and **the last `return` reached wins** (confirmed with a harness test), so both the "skipped" code and the value are wrong. Keep a single `return` at function level and use `if / else` (or a guarded value such as `depth = cond ? x : 0`). `tests/test_cepstra.js`, `tests/test_percipitator.js` and `tests/test_reciprocator.js` enforce this. It had silently broken Percipitator Freeze and silence sleep, and made Reciprocator's Soft/Hard Clip run as the Limiter.
     - Bind `Buffer varName("extName");` on `loadbang` using the **GenExpr variable name with no `set` prefix** (e.g., `scope #0-recipscope`).
   - **Real Max Audio Test Harness**: Every DSP device must have an automated Max audio test runner (`scripts/run_<device>_audio_tests.py`) built on the shared harness `scripts/max_harness.py` (see section 1b). It verifies audio behaviour and the live UI telemetry buffer updates.

## 1b. Real Max Test Harness (`scripts/max_harness.py`) — Mandatory for Every Max Test

All Max runs happen inside the `macos-01` VM (section 1a). Several agents may run standalone Max there at once. Every runner that launches Max must go through `scripts/max_harness.py`. Never start Max, `open` it, or write a launch loop yourself.

**What the harness does, and why** (all measured on this machine, 2026-10-19):
- **NonRealTime driver.** Each case renders on Max's `NonRealTime` audio driver (`; dsp setdriver NonRealTime`, `dsp sr 48000`). There's no hardware audio device to contend for, and renders run far faster than real time (most cases take 5–10 s, mostly launch time). On the hardware driver, overlapping runs produced partial or silent recordings.
- **One harness Max at a time, machine-wide.** Every case holds `/tmp/m4l_real_max.lock` (the same file `scripts/max_lock.py` uses) for the whole life of its Max. Max hands a newly launched patch to an already-running Max instance, even with a direct launch, so concurrent harness launches end up in one process: shared `rec` buffers, results read from another run, and one SIGTERM ending both. Separate parallel Max instances are not achievable by launching more processes of the same app. Runners may still call `run_case` from several threads or processes; the lock queues them. Before each launch and after each run, the harness kills any standalone harness Max still alive, so the next patch can't be handed to it.
- **Overdrive forced on.** Every patch sends `; max overdrive 1`. With Overdrive off, the scheduler-in-audio-thread setting (`takeover 1`) does nothing, and mid-run events never land: the host had Overdrive on in its prefs, the `macos-1` VM had it off, and every event was lost there.
- **No scheduler timing.** Under NonRealTime, scheduler milliseconds do not follow audio time: a "1000 ms" `delay` window held 144,000–244,000 samples. So no `delay`, `metro`, `pipe` or wall-clock timing anywhere in a harness patch. The scaffold records from DSP start and counts samples in gen. It copies the measured window (settle period dropped) into buffer `rec`, stamps it with the real DSP rate, then sends `analyze <dur_ms>` to the probe.
- **Direct launch.** Max is launched by exec'ing the binary with the patch in argv, plus `-ApplePersistenceIgnoreState YES`.
  - `open -n` makes the already-running Max quit, so parallel runs killed each other.
  - A direct exec from a background script keeps every instance alive and does not take screen focus.
  - A launch may forward its patch to a running instance and exit, so the launch PID is not the rendering process. The harness tracks Max by its unique temp patch path (`pgrep -f`). It finishes on the done marker, or on a non-empty result file that has stopped growing for 1 s.
  - Patch windows can't be hidden. Hiding the patch window (`this.patcher.wind.visible = 0`) stalled rendering completely. The Max Console window still appears briefly; leave it.
  - The flag skips the "reopen windows after a crash?" alert. Once Max had crashed a few times, that alert aborted every new launch.
- **No `; max quit`.** On this macOS / Max build it aborts in `maxapplication_quit` (`+[NSEvent startPeriodicEventsAfterDelay:...]` throws), which writes a crash report and shows a "Max quit unexpectedly" dialog. The scaffold writes a done marker instead, and the harness ends Max with SIGTERM, which is not a crash.
- **Timeouts.** Each case gets 300 s (`timeout=`).
- **Per-run isolation.**
  - Each run gets a unique temp dir and result path; the probe receives it as `resultpath <file>`.
  - Runner self-check: `scripts/run_max_harness_selftest.py` starts three runners at once with different durations, and each must get exactly its own window.
  - A result whose settle and duration don't match its own run is rejected.
  - Crash Recovery is cleared only when no other harness Max is running.
  - Max's `audioprefs.txt` is set back to Core Audio after the last harness Max exits, because `setdriver` persists.

**Writing a runner:**
```python
import max_harness as mh   # mh.box, mh.msg, mh.gen_box, mh.line, mh.samples_for_ms
r = mh.run_case(name, device_boxes, device_lines, probe_js=PROBE, probe_args="",
                settle_ms=300, dur_ms=500, channels=2, sr=48000, mode="nrt",
                events=[(at_ms_from_dsp_start, "target-id", inlet, "message")])
```
- The scaffold provides these ids, so don't reuse them:
  - `obj-load`: loadbang that fires before DSP starts. Send parameter and buffer-bind messages from it. If their order matters, sequence them yourself with a `t b b b`.
  - `obj-record`: connect the signals to analyze to inlets `0..channels-1`.
  - `obj-mute-l` / `obj-mute-r`: `*~ 0` into `dac~`.
  - `obj-js`: your probe.
  - `hx-*`.
- Probe engine: classic `js` by default; `probe_object="v8"` for ES6 probes.
- Name device-level buffers, sends and receives with `#0-`, as in the devices themselves. `rec` / `rec_full` belong to the scaffold.
- Probe contract:
  - `function resultpath(p) { resultPath = String(p); }`
  - `analyze <dur_ms>`: read buffer `rec`, write `key value` lines (one token per value) to `resultPath`, then bang the outlet.
  - Extra probe files go next to `resultPath`; read them with `keep_dir=True` and `r["harness_dir"]`.
- Reference consumer: `scripts/run_max_harness_selftest.py` (exact window, event timing, 3 parallel cases). Run it after changing the harness.

**Modes:**
- `nrt` (default): fastest.
- `stepped`: NonRealTime with `takeover 1`, so `events` land within one vector (measured 1 sample late on the host and in the VM). `run_case` switches any case with `events` to `stepped` automatically; under `nrt` the events miss their time.
- `audio_device`: the real CoreAudio driver, in real time (same machine-wide lock). Only for the few tests that depend on the hardware driver itself, such as real-time CPU load or device sample-rate switching. It must stay rare. Say why in a comment.

`scripts/max_lock.py` remains only for legacy, unmigrated runners; it uses the same lock. New runners never need it.

## 1c. Type-Checking Plain JS (`tsc --noEmit`, no TypeScript build)

Sources stay plain `.js`; nothing is compiled or emitted. TypeScript only checks them (`package.json` dev dependencies, run `npm install` once), so a typo in a Max API name or a cross-file function name fails before the build. `npm run typecheck` checks every device.
- **Max API types** come from DefinitelyTyped: `@types/maxmsp` (js / jsui / v8 / v8ui globals: `mgraphics`, `outlet`, `post`, `Buffer`, `Dict`, `Global`, `LiveAPI`, `Task`, `Patcher`, `Maxobj`, ...) and `@types/max-api` (Node for Max). `@types/node` is pinned to 22, the Node that Max 9 bundles (`v22.18.0`). What these lack or mistype goes in `src/types/max-extras.d.ts`; never silence an error with `any` or `@ts-ignore` in a source file.
- **One config per script group**: `tsconfig.<device>[-<part>].json` lists, in build order, `src/types/max-extras.d.ts`, the device's own `src/types/<device>.d.ts` (globals the build script injects, e.g. `FACE_REGION`) and every `.js` file the build concatenates into that one `v8ui` / `js` script. It extends `tsconfig.base.json` (`checkJs`, `lib: es2022`, no DOM, `strict` off), or `tsconfig.node.base.json` for `node.codebox` / `node.script` scripts. Groups stay separate because devices define the same globals (`paint`, `onclick`, ...).
- **Every gate starts with `npm run -s typecheck`** (all 28 configs, about 2 s). A new device or script group needs its own config before its first build, or it is silently unchecked.
- **Keep shared config files global scripts.** A top-level `module.exports = ...` makes TypeScript treat the file as a CommonJS module, and its functions vanish from the scripts it is prepended to. Export through a local: `var nodeModule = (typeof module !== "undefined") ? module : undefined; if (nodeModule && nodeModule.exports) nodeModule.exports = {...};`.
- **Fix inference with JSDoc**, e.g. `/** @type {Array<number | string>} */` on a mixed array. Untyped JS parameters are optional, so argument-count mistakes are only caught once a function has `@param` tags; add them to shared helpers as you touch them.

## 2. `.amxd` Binary Format Reference

An unencrypted Max for Live `.amxd` file consists of a 32-byte binary header followed by UTF-8 JSON patcher data:
- Bytes `0..7`: `b"ampf\x04\x00\x00\x00"`
- Bytes `8..11`: Device type 4CC:
  - `b"aaaa"` (`amxdtype: 1633771873` / `0x61616161`) — Max Audio Effect (`plugin~` / `plugout~`)
  - `b"mmmm"` (`amxdtype: 1835887981` / `0x6d6d6d6d`) — Max MIDI Effect (`midiin` / `midiout`)
  - `b"iiii"` (`amxdtype: 1768515945` / `0x69696969`) — Max Instrument
- Bytes `12..23`: `b"meta\x04\x00\x00\x00\x00\x00\x00\x00"`
- Bytes `24..27`: `b"ptch"`
- Bytes `28..31`: `uint32_le` length of the following JSON byte payload.
- Bytes `32..end`: UTF-8 encoded patcher JSON ending with `\n`.

### `v8ui` + Audio-Rate `buffer~` Integration
- `obj-mseg` (`maxclass: "v8ui"`) embeds the ES6+ script inline via `"textfile": { "text": ..., "filename": "none", "flags": 0, "embed": 1, "autowatch": 1 }`.
- `obj-buf` (`buffer~ #0-mseg @samps 4096`) holds the 4096-sample lookup table. On startup, `loadmess setbuffer #0-mseg` passes the unique `#0-mseg` buffer name to `v8ui`, which writes all 4096 samples via `new Buffer(bufName).poke(1, 0, samples)` whenever the curve changes.
- `v8ui` Outlet 0 emits `["loop", loopStart, loopSpan]` to window the MSP `phasor~` phase into `[loopStart, loopStart + loopSpan]`, and `["syncphase", phase]` to align `phasor~` with Ableton Live's 1-PPQ arrangement timeline position (`plugsync~` outlet 6) in Sync mode.
- `v8ui` Outlet 1 emits the LFO frequency in Hz to `phasor~` (automatically scaled by `1 / loopSpan` when a loop sub-region is active so tempo-synced subdivisions keep constant musical speed).

- `src/tinyspace_core.genexpr` — FDN: predelay → HP/LP → seeded allpasses → 20 delay lines (10 L / 10 R) with linear interpolation, per-line damping, soft clip, an orthogonal per-model mix (identity, sum-preserving rotation, Householder, Householder-cycle, sign-flipping ring, Householder wall-swap, spring lattice, or reversal), a unitary crossfeed rotation → width (M/S) → equal-power dry/wet.
- Audio is `in1`/`in2`. Knobs are Gen `Param`s (`size`, `damp`, `width`, `wet`, `fbk`, `predly`, `modamt`, `xfeed`, `hp`, `lp`, `duck`), sent with `prepend`.

Loadbang binds them with `cfg #0-tsconfig, meters #0-tsmeters` (the GenExpr variable, with no `set` prefix). An unbound buffer peeks as zeros, every delay line stays off, and Mix at 100% is silent.
- Percent knobs are scaled by `/ 100.` before they hit gen. Feedback uses a delay-style RT60 curve (`feedbackRt60`): about 0.7 s at 50%, about 2.7 s at 75%, and about 27.5 s at 100% (60 dB down). Every room model shares that tail because the mix is orthogonal and the all-ones mode has eigenvalue magnitude 1. The per-loop coefficient is higher on short lines so a small Size rings about as long as a long one, and it stays under 1. Feedback at 0 writes no recirculation. Delay taps are whole samples, and Damp at 0 is a bypass (`pole = 0`), so short combs stay metallic. Above 0, Damp is a per-pass one-pole on every delay tap, including the first reflection: about 5 kHz at 20%, about 1.8 kHz at 50%, and a few hundred hertz at 100% on an 8 ms line. Short lines use a higher cutoff so a 1 ms comb is not filtered much harder than a long room line. Every room model shares that filter. Crossfeed is a rotation (`xfeed * pi/2`), so a partial XFeed does not burn energy.

### Nested Rack ("Chain within a Chain") Scoping, Same-Chain (`Cmd+D`) Isolation & Cross-Instance Sync
- `parseRackContextFromPath(lomPath)` in `src/mbsplit_config.js` inspects `LiveAPI("this_device").unquotedpath` and extracts the **immediate enclosing `RackDevice` LOM path** (`parentRackPath`), **immediate enclosing `chains <N>` index** (`chainIndex`), and **device index within that chain** (`devices <D>` -> `deviceIndex`).
- **Nested Rack Scoping**: In `Auto` link mode, instances inside an outer Audio Effect Rack link exclusively with siblings in that outer rack and auto-create `1..4` bands matching the detected instances (`Chain 1..N -> Band 1..N`), while instances inside a nested sub-rack ("a chain within a chain") link exclusively with siblings inside that nested sub-rack.
- **Same-Chain (`Cmd+D`) Left-Most vs. Right-Hand Isolation**:
  - Within any chain `(parentRackPath, chainIndex)`, `isLeftMostInOwnChain()` and `getActiveGroupKey()` in `src/mbsplit_ui.js` compare alive splitters by `(deviceIndex, order, id)`.
  - Only the **left-most** splitter in each chain (`isLeftMostInOwnChain() === true`, e.g. `chains 0 devices 0`) joins `"rack_group::" + parentRackPath`.
  - Any splitter to the **right** in the same chain (`isLeftMostInOwnChain() === false`, such as a `Cmd+D` duplicate at `chains 0 devices 1` before it is grouped into a sub-rack) receives `"rack_group::isolated::" + INSTANCE_ID`, keeping it in its own empty `1`-band chain (`1:FULL`) with independent crossovers.
  - Reordering a right-hand splitter to `devices 0` or deleting the left-most splitter automatically promotes the new left-most splitter into `"rack_group::" + parentRackPath` and syncs the rack's `F1` / `F2` / `F3` / `Slope`.
- **Cross-Instance `LiveAPI("this_device")` Thread Safety & Allocation Reuse**:
  - In Max for Live (`v8ui`), calling `new LiveAPI(..., "this_device")` inside a cross-instance `Global` callback resolves `"this_device"` to the *caller's* patcher rather than the callee's patcher. Each instance therefore caches a single `selfLiveApi` bound on its own thread (`isOwnThread !== false`) and reuses `selfLiveApi.unquotedpath` during liveness and topology checks, preventing cross-instance path clobbering and main-thread `LiveAPI` allocation floods.
- Cross-instance synchronization uses `Global("mbsplit_shared_bus")` to link `F1` / `F2` / `F3`, `Slope`, `Phase Mode`, and auto-detected `NumBands` while keeping `BandMode`, `CustomMask`, and `Gain` (`-inf..+18 dB`) independent per chain.
- `SplitStateData` blob is version 3: `[3, f1, f2, f3, numBands, slope, bandMode, customMask, linkGroup, gainDb, showLinkStatus, phaseMode]` (v1 / v2 still load; they leave the phase mode alone).

### Dynamic Phase (`Phase Mode` = `DYN`, gen `dynphase 1`)
- **F1** stays the minimum-phase Linkwitz-Riley split (selected `Slope`). **F2 / F3** become complementary linear-phase FIR splits of the F1 high band: Kaiser (`beta 6`) windowed-sinc lowpass, symmetric half-length `D` taps, DC-normalized; `band2 = LP2 * hi`, `band3 = LP3 * hi - LP2 * hi`, `band4 = delay_D(hi) - LP3 * hi`, `band1 = delay_D(lo)` (`delay_D(x)` with 1 band). The sum is exactly the F1 allpass delayed by `D`, whatever the kernels are, so kernel redesigns (every 32 samples while F2 / F3 move) never break the flat sum.
- `D = 128 * round(sr / 48000)` clamped `128..512` (`128` at 44.1 / 48 kHz, about 2.7 ms; `256` at 96 kHz). F2 / F3 transition: about `sr / D` (375 Hz at 48 kHz) either side of the crossover, from -0.7 dB to below -60 dB, so slopes get gentle below about 300 Hz. That is why F1 stays IIR.
- Switching modes fades out for 4 ms, swaps, then fades in for 4 ms. The rings always run, so the new mode starts with valid history.
- **Latency reporting**: gen publishes `D` at `scope[26]` and the active mode at `scope[27]`. The v8ui calls `this.patcher.setattr("latency", phaseMode ? D : 0)` (`updateDeviceLatency()`). Live re-reads this at runtime: verified through the MCP bridge, where `latency_in_samples` followed the attribute immediately. Every linked instance carries the same phase mode, so all Rack chains report the same latency.
- JS mirror in `src/mbsplit_config.js`: `firLatencyForSampleRate`, `designFirHalfKernel`, `evalFirHalfKernel`, `computeFirLowpassMag` (raised-cosine display approximation, within 0.1 of the real kernel), and `createReferenceSplitterDsp(sr).processSampleDynamic`.

### Gen core (`gen.codebox~`, hidden)
- `src/mbsplit_core.genexpr` — Phase-compensated stereo Linkwitz-Riley crossover tree (`12 dB/oct` LR2, `24 dB/oct` LR4, `48 dB/oct` LR8) supporting `1..4` bands with matching allpass phase-compensation stages (`ap2_b1`, `ap3_b1`, `ap3_b2`) so parallel chains sum to a flat `0.000 dB` allpass unity response across all crossover frequencies, plus `-70..+18 dB` (`-inf..+18 dB`) output volume.

### Gen core (`gen.codebox~`, hidden)
- `src/cepstra_core.genexpr` — true cepstral formant shifter: STFT overlap-add with Hann analysis and Hann synthesis windows at 75% overlap (hop `N/4`, normalized by `1 / (N * 1.5)`), FFT size `N = 1024 * 2^quality` (`1024` / `2048` / `4096`), own radix-2 FFT written as GenExpr helper functions over `Data` arrays sized for `4096`, `float64` precision.
  - **Mid/Side packing**: `M = (L + R) / 2`, `S = (L - R) / 2`. `M + jS` share one complex FFT. Because both log-spectra and both cepstra are real and symmetric, the same packing carries them through all four FFTs per hop (forward FFT, cepstrum IFFT, envelope FFT, synthesis IFFT).
  - **Per-frame pipeline** (`job_*` functions): `logmag = log(|X| + 1e-9)` -> cepstrum `c = IFFT(logmag)` -> lifter (`|n| < L`, half-Hann taper over `clip(L / 4, 2, 6)` bins) -> envelope `E = FFT(formant cepstrum)` -> fine structure `H = logmag - E` -> shifted envelope `E'[k] = E[k / 2^(st/12)]` (linear interpolation, `midshift` for Mid, `sideshift` for Side) -> harmonic gate (`gate_h`, Spec mode: relative to the **local partial peak**, not the envelope. `job_spec` part 0 builds the peak envelope `P[k] = max_j (H[j] - d |k - j|)` of the fine structure in two O(N) passes (`d` = 1 neper per half harmonic spacing implied by the lifter, `W = N / 2L`; stored in `hre` / `him`, which only the Ceps path otherwise uses), then bins more than `8 + 40 * (1 - Gate)^3` dB below `P` are cut with a soft knee (up to 60 dB). So partials keep their level while the noise between them drops: on the 48 kHz test vowel + noise about 4 dB at 40%, 10 dB at 60%, 14 dB at 100%, f0 within 1.5 dB. An envelope-relative threshold (the old design) sat above most partial peaks, because `E` is a log *mean*, and attenuated partials and noise alike) -> output magnitude `exp(clip(E' + H_gated, -21, 12))` with the original phase (same for Side) -> IFFT -> synthesis window -> overlap-add. Neutral settings (`shift 0`, gate `0`) are an exact magnitude identity.
  - **Gate Mode** (`gatemode`: `0` Spec, `1` Ceps; Gate amount unchanged). `Spec` is the peak-relative spectral gate above (`gate_h` on `H[k]`; bypassed in Ceps mode). `Ceps` is a **voicing-keyed gate** (`job_cgate`, one job per frame, O(N/2)): pitchedness `v` = largest Mid cepstral peak in `max(L, 1 ms) .. 1/60 s` over the RMS of that region (about 3–4.5 for noise at any level, 5–11 for noisy voicing, ~25 for a clean vowel). Frames with `v` below `Tv = 3.5 * 7^Gate` (3.5 .. 24.5, soft knee ±1) are attenuated by up to 60 dB on both channels (stereo-linked log gain `stat[9]`, added in `job_spec`), smoothed across frames (open 0.7, close 0.25 per frame). So low settings gate unpitched content (breaths, hiss, noise) and higher settings let only cleaner pitched content through. `stat[8]` / `scope[263]` = `Tv * RMS` (in `|c|` units): the display's ± threshold lines are the level the pitch peak must cross for the gate to open. `stat[5]` stays 0, so the old harmonic-FFT slots in the schedule are idle (`jobCount` unchanged). At Gate 0 or in Spec mode the gain is 0 (exact identity, null test unchanged). The earlier coefficient-threshold cepstral gate was dropped: with only 2–5 rahmonics per 2048 frame, removing cepstral detail smooths the comb and *raised* the noise between partials at low settings. JS reference: `cepstralVoicing()` / `voicingThreshold()` / `voicingGateStep()` in `src/cepstra_config.js`.
  - **Cutoff modes** (`resmode`): `0` Manual (`res` -> `0.3 ms .. 15 ms`, logarithmic, clamped `< N/2`); `1` Auto (largest local maximum of the Mid cepstrum in `1/1000 s .. 1/60 s` with parabolic refinement and a `0.06` voicing threshold; `L = k * period`, `k = 0.3 + 0.7 * res`, held when unvoiced); `2` MIDI (`midinote` Param, `period = sr / mtof(note)`, same `k`, last value kept with no note). `L` is smoothed between frames (`0.4` per frame).
  - **Time-sliced work**: each frame is `5 * log2(N) + 11` jobs (one FFT pass or one slice of an O(N) loop each), spread across the first `N/8` samples of the hop, so no single sample runs more than one FFT pass. Latency is therefore `N + N/8` samples (`2304` at `2k`); the dry path is delayed by the same amount (`Data` ring) and Mix is equal-power.
  - **Quality switch**: changing `quality` aborts the in-flight frame, clears the overlap-add rings and mutes the output for `N + N/8 + 3 * hop + 256` samples with a 256-sample fade-in (brief mute, no crash).
  - **Silence sleep**: input below `-100 dB` (`0.00001`) for a whole frame (`quietCount >= N`) skips all FFT work (lossless: such a frame's output is zero); outputs go through `fixdenorm` / `fixnan`.
- `Buffer scope("cepscope")` (`272` samples), bound on `loadbang` via `scope #0-cepscope`: `0..191` the **signed** Mid cepstrum `c[n]` on 192 **linear** quefrency columns (`n = 0 .. 20 ms`, `qmax = 0.02 * samplerate`; each column keeps the bin with the largest `|c|` and its sign; `9999` = column at or beyond `N/2`), `256` current `L` in samples, `257` f0 estimate (Hz), `258` input level, `259` frame counter, `260` `N`, `261` voiced flag, `262` `resmode`, `263` Ceps-gate threshold for Mid in `|c|` units (`0` when inactive). Written once per frame.
- MIDI: `midiin` -> `midiparse` -> `unpack 0 0` -> `> 0` (velocity) opens a `gate` so only note-ons pass -> `prepend midinote` -> gen (and `prepend midi_note` -> `v8ui`). Note-offs close the gate, so the last note is kept.

### MIDI out from an audio effect (MidiRouter technique)
- **How it routes:** an Audio Effect sends MIDI to any track through a plain `midiout`, which goes to the device's LOM DeviceIO `this_device midi_outputs 0`. Setting that DeviceIO's `routing_type` / `routing_channel` gives the same "MIDI To" choice as External Instrument, and Live saves it with the set. Requires Live 11.0.5+.
- **Initialisation:** `live.thisdevice` → `init_routing` → `obj-viz` builds four `LiveAPI` observers (`available_routing_types`, `available_routing_channels`, `routing_type`, `routing_channel`). Never init from `loadbang`, because the LOM isn't ready yet.
- **Reading values in v8:** `get()` returns `["{json}"]`. Observer callbacks pass `[property, <Max Dict>]`, where the Dict is a handle like `{name: "u0950..."}` that must be read with `.stringify()`. `lomValue()` in `src/envtrig_config.js` handles every shape. Treating the Dict as data left the menus empty in Live.
- **Menus:** both are hidden parameters (`parameter_invisible: 2`, no initial value) that only mirror the LOM. `obj-viz` outlets 1 and 2 fill them with `_parameter_range` (undocumented) and `setsymbol`; their output comes back as `settype $1` / `setchannel $1`.
- **Destination track:** it must be monitoring (`In`, or `Auto` while armed) for its instrument to play.
- **Note path:** gen gate → `edge~` → `t b b`. The right outlet samples the held velocity with `snapshot~` into `makenote`'s velocity inlet; the left outlet sends `i <note>` to `makenote`'s pitch inlet. Then `pack 0 0` → `midiformat` (channel inlet 6) → `midiout`.
- **Timing:** notes are scheduler-timed (one audio vector of jitter), plus the 2.5 ms velocity capture.

### Gen core (`gen.codebox~`, hidden, 4 outlets)
- `src/envtrig_core.genexpr` — single band on the mono sum. Audio passes through untouched (`out1`/`out2`).
- **Envelopes:** a fast envelope (instant attack, 15 ms release) and a slow 60 ms baseline.
- **Onset:** fires when fast > `thr` and fast > slow × `(1 − sens) × 12 dB`, while armed and outside the `holdms` lockout.
- **Velocity:** a 2.5 ms capture of the peak, mapped from threshold..0 dBFS to `velmin..velmax`.
- **Gate:** high for `holdms / 2`, so `edge~` sees it at any vector size.
- **Re-arm:** below 70 % of the threshold, or back near the baseline.
- **Outlets:** `out3` gate, `out4` held velocity.
- **Naming:** never name a Param `hold`; with that name the lockout and gate outputs silently stopped working.
- **Telemetry:** `Buffer scope("trigscope")` (`buffer~ #0-trigscope @samps 800`, bound via `scope #0-trigscope`).
  - Written every 64 samples:
    - `0` fast env
    - `1` slow env
    - `2` fire counter
    - `3` roll
    - `4` input peak
    - `5` last velocity
  - Oscilloscope ring, one block per 32 samples:
    - `6` write head (`0..255`)
    - `32 + 3 × block` holds mono min, max, and an onset flag
    - The onset flag is set at the onset, not at the end of the velocity capture, so ticks line up with attacks.
  - Pokes stop once the device has been silent for a few windows.
  - The layout constants (`SCOPE_BLOCKS`, `SCOPE_RING_OFFSET`, `SCOPE_BUFFER_SAMPS`) live in `src/envtrig_config.js`. `tests/test_envtrig.js` checks that the build and the gen core match them.

### Performance
- **Gen:**
  - The `pow`/`exp` coefficients (threshold, onset ratio, envelope coefficients) are cached in `History`. They're recomputed only when `thr`, `sens` or the sample rate changes, not every sample.
  - The `log10` velocity math runs only when a note fires.
- **UI:**
  - The graph polls at 30 fps and stops redrawing once its history has scrolled flat in silence. A moving ring head, a new fire or a decaying LED wakes it again.
  - The envelope view reads only the 7-sample header. The 768-sample oscilloscope ring is copied only while the scope view is showing, and only when its head has moved.

Footer: `Use: keys from <slice_from>`, `Slice at: <Divisions | Beats | Onsets | Pitches | Manual>` with its amount (count, note value menu, or sensitivity %), and `Playback` (`slice_play`).

    - Cycles: `Pulse` (Formant, Width), `Partials` (Formant, Split, Fund.) or `Phase` (Formant, Mod, Harm.), plus `cy_xfade`.
    - Textures: Size, Spray, Fmt.
    - Fragments: grain envelope glyph (`fr_env`), `Rpt` (`fr_repeats`), Size / Density / Motion, and `fr_sync` / `fr_use_density` toggles.
  - Play panel: Freeze, Pitch, Speed (dimmed in Repitch) and Pos (dimmed unless frozen).
  - Filter panel.
  - Envelope panel: `AMP` / `MOD` / `LFO` / `UNI` pages.
- **Inspector**: Note Glide (`glide_ms` + `L` legato = `mono_legato`), then `<Mode> mode` settings.

  - Dragging a knob vertically covers its full range in 120 px, shift-drag is 8x finer, and double-click resets it.

  - Hovering or dragging a knob shows its value.

- **Loading a sample**: drop it on the waveform (`obj-drop-wave`), or click the file name (`browse` → `opendialog sound`). Both reach the face (`prepend dropfile` / `prepend browsed`), which emits `load_sample` → `prepend replace` → `buffer~ #0-bsamp`. The buffer's done bang → `prepend sample_loaded` → face.

Live then replays the saved path on Set load; `dropfile` ignores a replay of the path being restored. A dialog pick sends `drop_set` → `prepend set` → the drop zone. Keep exactly one `live.drop`.

### Gen core (`gen.codebox~`, hidden)
- `src/sampler_core.genexpr`: 16 voices, each with up to 8 stereo unison sub-voices.
- **Engines** (`mode`):
  - `0` Repitch, with characters (`rp_char`):
    - Clean.
    - Analog: saturator with pre/post EQ (`rp_dist`), and a tape stage (`rp_color`: + brighter, hiss, wow/flutter, azimuth; − low-mid, softer).
    - Digital: 13 bits at Dist 0 down to 2, sample-rate reduction for Color, plus `rp_vsr` and `rp_imaging`.
  - `1` Cycles, with `formant` and characters (`cy_char`):
    - Pulse: phase-distortion width.
    - Partials: odd/even `cy_split` plus a `cy_fund` sine.
    - Phase: dirty-sine PM, `cy_mod` / stepped `cy_harm`.
    - `cy_xfade` crossfades two windows.
  - `2` Textures: granular cloud.
  - `3` Spectral: phase vocoder at 75 % overlap, FFT 1024 / 2048 / 4096 by `sp_quality`, time-sliced like Cepstra.
    - Pitch is bin remapping. A smoothed-envelope formant stage gives Pure `formant` / `sp_shift`.
    - Reharm `sp_bend` and `sp_quant` (Octaves / Key with `sp_key` / `sp_scale`, `sp_quant_amt`) act on harmonics above 1.5 times the root fundamental, so they need a correct `root_note`.
    - Also `sp_onsets`, `sp_dispersion`, `sp_live`, `sp_rel_formant`.
    - **Only voices 0..3 run Spectral**: the face caps polyphony at 4 in this mode (`voiceCap()`).
  - `4` Fragments: grain pool capped at **32 per voice** (`fr_max_grains` is clamped), round-robin.
    - Each spawn starts `fr_repeats` grains one grain length apart.
    - Controls: `fr_density` / `fr_use_density`, `fr_env` shape, `fr_motion` (pan and playhead randomisation), `fr_direction`, `fr_latch`, `fr_repeat_init`, `fr_survive` (timer).
    - `fr_sync` snaps the grain size to beat multiples of `tempo`. The face observes `live_set tempo` and sends `tempo <bpm>` → `prepend tempo` → gen.
- **`sliced`** is orthogonal to the engine. Every engine reads the slice bounds from `#0-bsvoices` live (slots 4/5) and honours `slice_play` (0 slice end, 1 sample end, 2 one-way loop, 3 ping-pong) and reverse. Pitch ignores the note when sliced.
- Every engine also has `freeze`, the TPT SVF filter with drive, Amp / Mod ADSRs and the LFO.
- `play_pos` only applies while `freeze` is on.
- A mono buffer plays on both outputs (`channelmode="clamp"`).
- **Buffers**:
  - `#0-bsamp`: the sample.
  - `#0-bsvoices`: 16 x 8 voice slots.
  - `#0-bsscope`: telemetry 0..39, plus 48 for the cumulative Fragments grain count.
- **One compiled voice engine (load time)**: GenExpr inlines every call, so the 16 voices run in one `for (vox = 0; vox < 16; ...)` loop around a single `voice_proc` call site, and the 4 Spectral voices in one `for (svx = 0; svx < 4; ...)` loop around `spec_voice`.
  - A call site's `History` is shared across loop iterations, so all per-voice state lives in `Data vhist` (256 slots per voice) and `Data sdat` (one block per Spectral voice). Non-zero initial values are written once in the `initDone` block.
  - Released, silent voices with no Fragments tail skip `voice_proc` and output exact zeros.
  - Gen compile went from about 4.9 s to 1.3 s in the VM (`python3 scripts/measure_sampler_loadtime.py 3`, `gen - baseline`, run in the VM). Keep it under 1.5 s: never add a second call site of a big helper.
- **Gen gotchas found here**:
  - A function-local variable with the same name as a global `Data` (e.g. `hs`) silently breaks compilation: no output and `scopeFrames` 0.
  - A `Data` declared inside a function is shared by all its call sites, so per-voice state lives in global `Data` with offsets.
  - `int(clip(round(peek(...))))` misbehaved; use `floor(x + 0.5)`.
  - **Cycles pitch**: both overlap-add grains must read the source at the *same* phase (`pNext`); only the Hann window (offset 0.5) and the latched anchor differ. Reading grain B at `pNext + 0.5` made a periodic source sum to `-sin(2x)` and sounded an octave high (440 Hz instead of 220 Hz at the root). `run_sampler_audio_tests.py` now asserts 220 Hz at the root and 440 Hz an octave up for Pulse / Partials / Phase and `cy_xfade`.
- **CPU** (VM, one core, including about 9 % harness floor, idle / 4 voices): Repitch 8 / 10 % (Analog 8 / 11 %, Digital 7 / 11 %), Cycles 8 / 9 %, Textures 7 / 9 %, Spectral 7–8 / 16–18 %, Fragments 7 / 13 %.
- `src/sampler_config.js`: voice allocator (`setSliceBaseNote`, `updateSliceBounds`), `activeSliceStarts`, the slicers (`sliceDivisions`, `sliceBeats`, `bpmFromName`, `sliceOnsets`, `slicePitches`, `addSliceMarker`, `removeSliceMarker`) and `estimateRootMidiNote`.

### State
- `SamplerStateData` (blob, `parameter_type: 3`, on `obj-viz`) is saved by `getvalueof()`.
- Version 3 holds `[3, mode, start, end, loopMode, loopStart, loopEnd, xfade, playPos, envPage, sliceCount, ...slices, path]`, with positions stored as `x 10000`. In v1 and v2, `mode 3` was the Slice engine and restores as `sliced 1, mode 0`. v1 has no path.
- On a v2 restore it emits `load_sample <path>`, which goes `prepend replace` → `buffer~ #0-bsamp`. It sends it again from `setbuffers()` if the buffer is still silent, and keeps the saved slices instead of re-detecting them.
- The `live.drop` stays `parameter_enable 0`; the path lives only in the blob.

## 15. Architecture of `devices/Delay+.amxd` + `devices/Delay+ End.amxd` (two-device delay, feedback through a Live device chain)

### Topology
- Bitwig Delay+ style: the delay's tank feeds a chain of **real Live devices**. M4L cannot host devices, so it is two devices in one Audio Effect Rack chain: `[Delay+] [user FX ...] [Delay+ End]` (`devices/Delay+.adg` ships the rack with an empty middle). Delay+ (the Start) outputs **only the delay tap** into the chain; the End mixes dry + processed wet and writes the processed wet back to the Start as the feedback return. So both the first echo and every repeat go through the FX.
- `Delay+ End` (124 px) only shows link status, the latency in use, the debug ping result and wet/dry meters. All controls live on Delay+.
- Unpaired Start passes dry through; an End without a live Start passes its input through.

### Presentation Layout (`492 x 169` px, a copy of Ableton's Echo face — `scripts/delayplus_layouts/echo.py`)
- The face copies Echo control for control (Live theme colours: no colour attributes on the `live.*` objects), except that Echo's tunnel is replaced by the tape-loop ring and Echo's reverb is left out (its slot holds `Freeze` and `Debug`). Reference screenshots of Echo: Sound On Sound "Echo in Ableton Live" and PCAudioLabs' Echo series; the manual's Echo section documents every control.
- **Left column**: `Left` / `Right` delay dials (each side's `Sync` button swaps `Left Time` (ms) and `Left Division` (note value) in the same rect via `hidden`), the Stereo Link icon between them, per side `Sync`, the `Sync Mode` menu (`Notes` / `Triplet` / `Dotted`; Echo's `16th` mode is not implemented) and `Offset` (+-33 %), then `Input` with `D` (Clip Dry) and `Ø` (Feedback Invert), and `Feedback`.
- **Centre**: `[Echo | Modulation | Character]` tabs (hidden UI-state parameter `Delay+ Page`).
  - **Echo**: the ring display (`obj-viz`, `src/delayplus_ui.js` + `src/delayplus_viz_b.js`: status pill, tape-loop ring in Echo's orange / white / blue, no text) and Echo's bottom row: the Filter Display triangle, `Filter` on, `HP`, `Res`, `LP`, `Res`. The triangle shows / hides the **Filter Display** (`obj-filtdisp`, `src/delayplus_filter.js`, its own panel; dots draggable: x = cutoff, y = resonance, double-click resets) and the ring shrinks to the top part of the display (`presentation_rect` message to `obj-viz`).
  - **Modulation**: the LFO display (`obj-lfodisp`, `src/delayplus_lfo.js`: L blue / R orange waveforms, live dots from the scope telemetry, clickable waveform icons -> `Mod Waveform`), then `Sync` / `Rate` (Hz or note value) / `Phase`, `x4` and `Mod Delay`, `Mod Filter`, `Env Mix`.
  - **Character**: `Gate`, `Ducking`, `Noise`, `Wobble` sections (on toggle + two values each) and `Repitch`.
- **Right column**: `Freeze`, `Debug`, `Stereo` (width), `Output`, the `Stereo` / `Ping Pong` / `Mid/Side` stack, `Dry/Wet`.

All three inputs are stored parameters, so the state comes back on load. Live's UI font has no triangle / link glyphs, so those two toggles are tiny icon v8uis (`src/delayplus_icon.js`, `DP_ICON` set per instance by the build) driving `live.text` parameters that stay out of the presentation.
- **Stereo Link** is done in the face script: a change of one side's time, Sync or Sync Mode is sent to the other side's control with `set` (outlet 1 `mirror <key> <v>` -> `route` -> `prepend set`), which does not output, so it cannot loop.
- **Times / LFO rate** are computed in the face (`dpSideMs`, `dpLfoHz` in `src/delayplus_config.js`) and poked into the gen header (`hdr[31]` left / mid ms, `hdr[28]` right / side ms, `hdr[27]` LFO Hz).
- `scripts/build_delayplus.py` holds the parameter table `P` (Echo-style long names); a layout module must present every key exactly once and may declare extra displays (`v8uis`: script, rect, the keys whose `set_<key>` they receive, telemetry `names`, `icon`).

- **Theme colours** (follow Live's theme and hue, like Echo): patcher objects bind colour attributes with `"saved_attribute_attributes": {"<attr>": {"expression": "themecolor.live_..."}}` next to a static fallback (`theme()` helper in `scripts/build_delayplus.py`). A `panel` must bind **`bgfillcolor`** (what it paints with; Ableton's own patches do this), binding `bgcolor` changes nothing. v8ui scripts read `max.getcolor("live_...")` via `dpTheme(name, fallback)` on every paint and `dpThemeWatch()` redraws once a second if the theme changed. Names used: `live_lcd_bg` (displays, selected tab), `live_surface_bg` (side sections), `live_lcd_title` / `live_lcd_control_fg` (display labels / values), `live_display_line_one/two`, `live_display_handle_one/two`, `live_display_scale_text`, `live_lcd_frame`, `live_control_bg/fg`, `live_control_selection`, `live_alert`.
- **Parameter names in Live are the short names** (`parameter_shortname`): the LOM `name` / `original_name` and Live's automation and mapping lists use them (verified in Live 12.4.6), so every short name in `P` must be unique (`L Division`, `Gate Thr`, `Duck Rel`, ...). ### DSP additions (Echo controls)
- Start: per-side times, Mid/Side (the tank runs in M/S; taps are converted back to L/R before the chain, the return to M/S before the tank), Ping Pong, Input gain + Clip Dry + Gate on the signal entering the tank only, Feedback Invert, filter on/off with resonance (`k = 1.4142 * (1 - 0.95 * res)`) and LFO filter modulation (+-2 octaves), LFO (6 shapes, right-channel phase, x4, blended with an input envelope by `Env Mix`) on the delay time, Wobble (random wow / flutter, morph), Noise in the loop (hiss -> crackle), Repitch (tape glide vs crossfade).
- End: Ducking (threshold / release on the dry level, up to -24 dB) and Output gain on the wet, read from `hdr[40..42]`.
- The tank write soft-limits where input and feedback meet (linear below 1, tanh knee to 1.8), inlined in the main body: the same expression as a GenExpr helper function that declares a local variable made the whole Start gen fail to compile in Max 9.1 (identity helpers compiled).

### Cross-device transfer (`src/delayplus_start.genexpr`, `src/delayplus_end.genexpr`)
- **Buffer names use M4L's `---` prefix** (`buffer~ ---dpxfer`, also in the message boxes). In Live, `#0` is NOT expanded in a device's top-level patcher (only in abstractions): with `#0-` names every Delay+ instance shared one header and transfer buffer, which looked like random timing jitter with more than one pair.
- Shared buffers live in the Start: `buffer~ ---dpxfer @samps 65536 @chans 5` (ch0/1 dry at Start index, ch2/3 return at End index, ch4 whitened mono tap) and `buffer~ ---dphdr @samps 64` (header; layout in the Start genexpr comment). The End's gen binds to them by name (`xfer <name>`, `hdr <name>`) from its link layer; until then it uses its own empty `---dpxferE` / `---dphdrE`.
- Each device runs a free counter (mod 2^22) and pokes it to the header. In Live, devices of one chain run in 32-sample vectors in chain order. End: K (End's sample `cE` carries Start's sample `cE + K`) = held min of `cS_latest - cE` (8 windows), **then calibrated from the audio**: every 8192 samples End cross-correlates its whitened input against Start's whitened tap (xfer ch4) over 128 candidate K around that anchor and adopts an unambiguous peak seen twice (`hdr[18]` = calibrated). Start: `Smax` = held max of `cS - cE_latest`; it reads the return at End index `s - Smax` (always written) and `B = Smax - K` (hdr[3]).
- **Latency compensation**: End reads dry at Start index `cE + K - L` (aligned with the wet; Live's PDC then delays the track by L). Start adds the return into the tank at `s - B - L` (the tap's original emit position), so the tap re-reads it exactly T later: echoes land on n * T for any chain latency. Requires `T > B + L + mod + 4` -> clamped, `MIN x ms` shown in the header (`scope[2]`, `scope[3]`). Any change of L / B / K ducks the loop for 2048 samples.
- `L` = sum of `latency_in_samples` of the devices strictly between the pair, polled by the Start's link layer every 500 ms and **poked into `hdr[30]`** (the delay time in ms goes to `hdr[31]`). Messages sent to gen from the link layer's Task stopped arriving in Live, so values are written to the header buffer directly; the `lat` / `tms` gen Params remain for the standalone harness.

### Link layer (`src/delayplus_link.js`, shared by Start and End v8ui)
- Registry `Global("delayplus_bus").reg[<LOM device id>] = {role, xfer, hdr, t, polls, sentLat, lats, status}`, refreshed every 500 ms on each instance's own Task (stale after 3 s). Pairing = bracket matching over the own chain's device list (`dpFindPartner` in `src/delayplus_config.js`), so nested pairs and renamed devices work. All LiveAPI calls run on the instance's own Task, never in another instance's callback.
- Tempo sync: the Start observes `live_set tempo` and sends `tms` (ms) to gen (`dpTargetMs`).

### Debug mode (`Debug` parameter)
- Replaces the echoes with an impulse every 0.5 s (tank input and feedback muted, End mutes wet). End records its arrival (`hdr[10]`, ping-measured latency, must equal LOM `L`); Start records where the returning ping would be written relative to its emit index (`hdr[17]`, must be 0). The Start header and the End face show the result (`PING 256 ✓`).

## 16. Shared Cepstrum Engine (`src/cepstrum_lib.genexpr`) — Used by Phase Fold, Quefrency Crush, Timbre Follower

- GenExpr helper functions prepended by each build script to its own `*_core.genexpr`. The header comment holds the full API and a core skeleton; `tests/cepstrum_lib_core.genexpr` is a runnable example and `src/cepstrum_ref.js` is the Node reference mirror used by every device unit test.
- **Data is passed by reference**: functions take `Data` arguments, but a function body cannot see a global `Data`, so the core declares `tab(4096,3)`, `win(4096)`, `fx(4096,2)`, `fc(4096,2)` plus per-channel `ring(4096)`, `acc(4096)`, `st(4)` and passes them in.
- API: `fft_init`, `fft_run(x,tab,n,inv)`, `stft_win`, `stft_in` (returns 1 at a hop, hop = N/4), `stft_frame`, `stft_ola`, `stft_out`, `cep_from_spec`, `cep_fold_minphase`, `cep_fold_maxphase`, `cep_to_logmag`, `cep_exp_spec`, `cep_remag`, `cep_peak`, `cep_peak_conf`, `cep_peak_refine`. N is a runtime power of two (512..4096).
- **Latency**: the STFT path is `N - 1` samples. Live's device latency is the static patcher attribute `"latency"` (no runtime message exists), so every device with a selectable `Size` pads the wet path with a `Delay` to a constant **4096** samples, delays dry identically, and sets `"latency": 4096`.
- Tests: `node tests/test_cepstrum_lib.js`; real Max: `python3 scripts/run_cepstrum_lib_audio_tests.py`.
- **GenExpr gotchas learned here** (all cost hours):
  - Never name identifiers `phi`, `pi` or `e<digits>` — they are built-in constants (a `phi` upper bound once silently shrank a pitch-peak search to one bin).
  - A variable first assigned inside an `if` block is not visible after it; use top-level temps or `x = cond ? a : x`. Values computed at hop time are safest written to a `Data` slot and read with `peek` at top level.
  - `wrap()` with a non-constant upper bound fails codegen with `use of undeclared identifier 'v_NN'`; use explicit arithmetic.
  - `z = fn(d);` with `z` unused is dead-code-eliminated — call work functions as bare statements.
  - A `History` written this sample reads back its old value.

## 18. Architecture of `devices/Phase Fold A.amxd`, `Phase Fold B.amxd`, `Phase Fold C.amxd`

Cepstral phase sculptor: per STFT frame the real cepstrum is re-weighted asymmetrically (`ĉ[n] = c[n]·(1 ± p)`) and the spectrum rebuilt — `Phase +100 %` = minimum-phase (energy pushed forward, tight transients), `0` = zero-phase smear, `−100 %` = maximum-phase (reverse swells / pre-ring without reversing audio). Larger `Size` = longer swells.

- **Variants** (169 px high, `latency: 4096`): **A, 408 px** — in/out envelope canvas, frame-centroid strip and a draggable Phase handle field (MAX ↔ MIN) + value bars; **B, 300 px** — small scope strip over `Phase`, `Orig`, `Mix`, `Out` dials; **C, 440 px** — "transient lab" before/after waveform lanes with the Phase handle and a bottom control strip.
- Params: `Phase` −100..+100 % (default −50), `Size` 512..4096 (default 2048), `Orig` 0..100 % (complex-domain blend back toward the original-phase spectrum), `Auto Gain`, `Mix`, `Output`.
- **Crispiness fixes** (measured with `tests/phasefold_metrics.js`, regression-tested against `tests/phasefold_legacy_model.js` in `tests/test_phasefold.js`; A/B WAVs: `node tests/render_phasefold_ab.js` -> `tests/out/phasefold_ab/`):
  - **Crest limiter** (`pf_limit`): the rebuilt phase of a noisy frame is one click (flat magnitude = minimum phase = impulse), so noise became a hop-rate click train (white noise ripple 2.8..4.3 dB, crest +19 dB). A frame may be at most 8 dB spikier than the input frame, else it is blended (1/8 steps) toward the input frame. Real clicks (crest not increased) are untouched.
  - **Signed pivot** (`pf_pivot`): the pivot is the strongest *signed* `n/64` stretch of the windowed L+R input, not the loudest energy. The energy criterion flipped between the positive and negative crest of a periodic wave (13..25 dB AM on a sine, +6 dB floor between saw harmonics).
  - **2N zero-padded cepstral path** (`pf_fft`, own 8192-point FFT because the library one stops at 4096): min/max-phase tails of narrow-band frames are dropped past `n`, not wrapped into the frame. `tab`, `fx`, `fc`, `xo` are `8192`-long.
  - **Relative log floor**: `eps = max(peak |X| - 50 dB, 1e-9)`, taken out again by exp, so the magnitude stays exact while empty bins stop shaping the phase.
  - **Level**: `Auto Gain` = `sqrt(eiS / eoS) * 1.1`, one-poles (0.25 per frame) of the input frame energy and of the energy of the frame actually added, clipped `0.25..4`, slewed over 20 ms, faded to 1 toward `Orig 100 %` (exact identity). Frame energies, not sample energies: a sample-wise ratio squashes a pre-ring where the input is still silent. Level spread across Phase < 1.5 dB.
  - Known limit: tonal material with non-harmonic partials (chord) still shows ~3 dB of hop-rate ripple (input ~2 dB), because the pivot is not locked to every partial's phase.
- Telemetry: `buffer~ #0-phasefoldscope`. Node mirror of the core: `tests/phasefold_model.js`.

## 19. Architecture of `devices/Quefrency Crush A.amxd`, `Quefrency Crush B.amxd`, `Quefrency Crush C.amxd`

Creative cepstral codec: mangles the real cepstrum, then rebuilds the log-magnitude spectrum (energy + loudness matched, wet padded to 4096, Size changes bridged via dry). Processing order: Lag -> Glitch source -> Hold -> Scramble -> Shift -> Coeffs -> Bits -> phase rebuild (Phase mode).

- **Variants** (169 px high, `latency: 4096`, one v8ui `src/qcrush_ui.js`, 12 Live parameters each): **A, 520 px** — coefficient-bar canvas hero (284 x 134: original ghost vs crushed bars, EXC strip, Glitch clock, frame-history strip, Phase glyph, Lag spread, ENV; drag sets Coeffs) + eleven value-bar rows; **B, 520 px** — compact canvas beside a Degrade-style LCD `1.SIZE / 2.SCRAMBLE (+Amt) / 3.GLITCH (+Rate) / 4.PHASE (+Lag)` over five dials; **C, 500 px** — Coeffs x Bits crush pad over the bars, a Glitch pad face (`obj-glitch-face`, click cycles Off..Frz), Glitch tab, Rate menu, Phase tab, five dials + Scramble tab.
- Params (12): `Size` 512/1k/2k/4k, `Coeffs` (truncation), `Bits` 1..16, `Scramble` Off/Rev/Shuf/Rot, `Amount` (scramble blend / rotation **and** the chance that a Glitch slot fires), `Shift` ±12 st, `Glitch` Off/Drop/Rpt/Rev/Hold/Frz, `Rate` 1/32..1 bar (Glitch slot length, tempo-synced and host-locked), `Phase` Orig/Robot/Whisp/Min, `Lag` 0..100 %, `Mix`, `Output`. Freeze and Hold are no longer parameters: they are the Glitch modes `Frz` and `Hold` (Hold re-freezes at the Rate period, identical to the old Hold). Neutral = Glitch Off / Phase Orig / Lag 0 and is bit-identical to the version before these features (`tests/qcrush_legacy_model.js` is a frozen copy of the old Node model; `tests/qcrush_dsp_tests.js` compares them bin for bin).
- **Glitch** (`qc_select`): Rate slots on the host-locked beat (`plugsync~` ppq, same clock as Hold); slot `floor(beat / period)` fires when `hash(slot) < Amount`, so a loop or re-render repeats the same events. A ring holds the last 32 *received* cepstral frames per channel (`Data rgL/rgR`, 2050 floats per frame, only `c[0..N/2]`). While a slot is active the live frame is not stored (the ring freezes): **Drop** holds the last received frame and fades it 0.5^k per lost frame (packet-loss concealment, silent after a few frames), **Rpt** loops the last W received frames oldest to newest, **Rev** reads them backwards (W = half a slot in frames, clamped 1..8, and to what the ring holds). Only magnitude (cepstrum) comes from the ring; the live phase keeps moving, so nothing clicks (tested bin for bin).
- **Lag** (`qc_lagtab`, `qc_select`): coefficient q >= 1 is read `floor(12 * Lag * s(q) + 0.5)` frames back, `s(q) = 0.5 * min(1, (q-1)/127) + 0.5 * hash(q, 4.1414)` (index ramp + fixed seeded spread, spread computed once). c0 (level) is never delayed; Lag 0 (or below 0.1 %) skips the ring. Lag composes with Glitch (read relative to the glitch-selected frame). Max delay 12 frames, ring depth 32.
- **Phase** (`qc_phase`): `Orig` = the old remag on the input phase. `Robot` = zero phase moved to the frame centre by `(-1)^k` (monotone buzz at the hop rate N/4, so Size sets its pitch; a pure sine beats against the hop). `Whisp` = random phase per bin and frame, Hermitian, seed = host-locked hop index (+77 on the right channel). `Min` = minimum phase of the crushed log magnitude, reusing the Phase Fold fixes (section 18): relative log floor (peak - 50 dB), causal fold of the cepstrum evaluated on a zero-padded **2N** grid (own 8192 FFT `qc_fft`, tail past N dropped not wrapped), delay to the signed pivot of the input frame (`qc_pivot`), and a crest limiter (at most 8 dB spikier than the input frame, else blended toward it). Level: Robot / Whisp / Min frames are matched to the input frame energy (`qc_pgain`, one-poled 0.25 per frame, x1.45 / x1.41 / x1.1 because unrelated-phase frames add as powers); steady-state level within 1.5 dB of the input on speech-like, noise and saw material at N = 1024. Known limits: Min with Coeffs below ~60 % (envelope only, one pulse per hop) is a punchy hop-rate buzz; heavily low-passed noise shows a few dB of hop-rate ripple.
- Soft knee and loudness-match AGC apply whenever any new feature is on (`neuE`), as they do for any crush; with all neutral the output stage is untouched.
- **CPU**: neutral costs nothing extra. Glitch Drop/Rpt/Rev and Lag add a ring store and read of N/2 floats per frame per channel (no FFT); Robot adds one pass; Whisp adds N/2 sin/cos/hash per frame per channel; Min adds an N-point IFFT plus two 2N FFTs per frame per channel (about 2.4x the base per-frame cost, only while Phase = Min). Ring memory 2 x 65600 floats; lag spread table computed once.
- Telemetry: `buffer~ #0-qcrushscope` (320 floats; 0..305 as before, `306/307` 24-frame event history packed 2 bits per frame (0 normal, 1 dropped, 2 repeat, 3 reverse), `308` Glitch mode, `309` Phase mode, `310` Lag, `311` slot phase, `312` slot fired, `313` loop window W, `314` slot counter, `315` Drop fade gain, `316` loop position). Node reference: `src/qcrush_ref.js` (`DeviceModel` mirrors the whole control block and one channel).
- **GenExpr checked in Node**: `tests/genexpr_functions.js` transpiles the plain functions of `cepstrum_lib.genexpr` + `qcrush_core.genexpr` to JS (Data arguments bounds-checked) and `tests/qcrush_dsp_tests.js` runs `qc_select`, `qc_proc`, `qc_phase`, `qc_min`, ... against the mirror frame for frame. It cannot see GenExpr-only semantics (variable scope in `if`, DCE), so the real-Max runner still matters; every new function has a single `return` at function level (linted).

The MSEG is 94 px high in both modes (the presets row ends at y = 159) and the editor sits in an orange frame in Remote. **Mod mode**: to the right of the MSEG a **centred output bar** (Phase Plant style, a bar instead of a dot): zero is the vertical centre, positive output fills up from it, negative down. One limit triangle sets `range` (its distance from the centre, the whole Mod depth): `+` shows only the upper triangle, `−` only the lower one (the zero marker is hidden, fixed at the centre and not a hit target; a press on the hidden side is ignored and a drag past the centre pins range to 0), `±` shows both triangles linked symmetrically (either one sets the range). Double-click = range 1. The band covers centre..limit (both sides in `±`); the fill is the live signed modulation `o`. With the modulator bypassed the editor and bar draw grey and the scan line / live value are hidden, but everything stays editable. It reuses the modulator MSEG editor's point model and gestures (`ubMsegTgt` / `ubMapTgt`).
  - **Remote editor** (`mode: "remote"`): no polarity control, no centred bar. Two **independent** limits `min` / `max` (absolute 0..1 of the target; min > max inverts). The Remote colour is the orange `UB_REM_COL`: the lit `REM` tab, the frame and tint around the tab row and MSEG, and the curve. The bar right of the MSEG is an **absolute 0..1 bar** (no centre line) with two independent triangles, max filled and min outlined; the nearest triangle wins when you grab, double-click resets that one to 0 / 1; the min..max band is shaded and the live fill runs from min to the live value. Each triangle sets only its own field. The detail panel has no mode branches left: one layout, built by `ubDetailRects` and painted by `ubPaintDetail`.
  - The list-row value drag in Remote shifts min and max together (width kept).
  - The remap editor sits on its own rounded panel (`UB_PANEL_W` 144 px, `ubListGeom().panel`, same fill / stroke / top / bottom as the list panel) with 6 px side padding; the range readout is plain text at the right end of the presets row (the 5 presets shrink to leave room).
- **Pool full**: a red pill "Mapping pool full (256)" shows when the mapper fires change kind `"full"`.
- **Width**: the UI computes its layout width and calls `MM.requestWidth(w)`, which goes `width <w>` → `prepend setwidth` → `live.thisdevice`. `resizeFace()` grows the v8ui and every full-width background panel (looked up by varname = box id) with it.

### Engine (`gen.codebox~`, varname `megamod_engine`, hidden)
- **Slots**: 16 slots, all computed at audio rate. Per-slot config comes from `Buffer cfg("megamodcfg")` (16 × 24 floats). MSEG tables come from `megamodmseg` (16 × 1024) and steps from `megamodsteps` (16 × 32).
- **Inputs**: the mono sum (for followers) and transport from `plugsync~` (`hplay`, `hbpm`, `hppq` Params).
- **Outputs**: 16 signal outlets. Every generator yields `u` in 0..1. Bipolar output is `depth*(2u-1)`; unipolar output is `2*depth*u-1`, so the full −1..1 range always reaches the transfer table.
- **Telemetry**: `megamodscope` (128 samples). Slot `s` writes `[out, phase, u, aux]` at `4*s`. The header holds frame, sr, beat, bpm and playing at `64..68`.

### Mapping pool (saved objects, no runtime scripting)
- **Why**: `live.modulate~` / `live.remote~` objects **created by JS scripting in a running device never attach to a parameter in Live**: no modulation ring, no value change. This was verified through the MCP bridge. Every mapping object must therefore be saved in the device file.
- **Routers**: the build generates **8 router `gen.codebox~`** boxes, each with 16 inlets (wired from the 16 engine outlets) and 32 outlets. Slot `k` = router `floor(k/32)`, outlet `k%32`.
  - Each slot reads `route[2k]` (source modulator index, or −1 when off) from `megamodroute` (512 samples).
  - It looks up its 256-sample region `k*256` of `mmcurve` (fixed at 256 × 256), with the same convention as `lookup~`: index `(x+1)/2 * 256`, linear interpolation, clamped to the last sample.
  - The whole mapping transform is baked into that table, so editing a range or the curve only rewrites 256 samples: `mappingOutput(m, x)` = evaluate `m.shape` (MSEG points) at `u = (x+1)/2` and apply the Mod polarity / range or the Remote min / max formulas (see State). The router itself did not change.
- **Per-slot objects**:
  - `live.modulate~ @smoothing 1`, varname `mm_mod_<k>`.
  - `live.remote~ @normalized 1`, varname `mm_rem_<k>`.
  - Two `prepend id` boxes, `mm_mid_<k>` and `mm_rid_<k>`, wired to the **right inlet** of each. `id` must arrive on the right inlet; `Maxobj.message()` only reaches the left inlet.
  - The mapper binds the active mode's object and sends `id 0` to the other one. It always unbinds before binding, and on delete it unbinds both and sets the route to −1.
  - Slots are allocated lowest-free and reassigned on load. The 257th `addMapping` returns `null` and fires `"full"`.

### Learn
- **Observer**: `init_lom` (from `live.thisdevice`, never `loadbang`) observes `live_set view selected_parameter`. LiveAPI observers pass **one array** (`["selected_parameter", "id", N]` or `["id", N]`); flatten it before parsing.
- **Deferral**: the selection is handled on the next scheduler tick (`Task.schedule(0)`). Never read the LOM or touch objects inside a Live notification.
- **Lookup**: `describeParameter` uses a fresh `new LiveAPI(cb, "id N")`. Reusing a `goto` on a shared API returned nothing.
- **Rejected selections**: the device's own parameters and duplicates (same modulator + same target) are ignored.
- **Persistence**: targets are stored by LOM path plus track/device/parameter names. On load they are resolved by path first, then by name among top-level devices. Unresolved mappings are kept and marked `missing`, and a 1.5 s poll revives them or flags them.

### State
- The `MegaModState` blob (`parameter_type: 3`, v8ui `getvalueof` / `setvalueof`) holds the versioned JSON state, which covers the modulators, the mappings and an opaque `ui` object (selection, expanded strip, list open, scroll, selected mapping, strip order). Older versions still parse.
- **Schema 6** (`MEGAMOD_VERSION`): a mapping is `{id, mod, enabled, mode, polarity, range, min, max, shape, target}`; `amount`, `invert` and `bipolar` are gone. `min` / `max` (0..1, defaults 0 / 1) are the independent absolute limits used **only in Remote**; `polarity` and `range` are used only in Mod and are ignored (but kept, so switching mode restores them) in Remote. `polarity` is `1` (`+`), `0` (`±`) or `−1` (`−`); `range` is 0..1 (the limit marker's distance from the output bar's centre, the whole Mod depth). Defaults: `±`, range 0.5 (the same depth as the old amount 0.5 × range 1). With `y = evalMseg(shape, (x+1)/2)`:
  - signed modulation `o = range * (polarity === 0 ? 2y-1 : polarity * y)`, in −1..1.
  - **Mod**: `mappingOutput = o` (the offset `live.modulate~` gets).
  - **Remote** (`live.remote~ @normalized`, absolute 0..1): `mappingOutput = clamp(min + (max − min) * y, 0, 1)`; polarity / range are ignored.
  - **Migration schema < 6 (amount folded into range)**, Mod and Remote mappings alike: `range' = clamp(|amount| * range, 0, 1)`. If `amount < 0`, `+` and `−` swap polarity; for `±` the shape is flipped vertically (`y → 1 − y` on every point; `curve` / `sCurve` stay as they are, because the segment easing is a fraction of the y span, so `evalMseg` of the flipped points is exactly `1 − y`). Tables match the old `amount * range * (...)` within 1e-9 (measured 2.2e-16 over every polarity, amount sign 1 / 0.5 / 0.2 / −0.2 / −0.5 / −1 and range). Remote tables are unchanged (the folded polarity / range keep a later switch back to Mod identical to the old Mod output). Older schemas run through the chain below first. A stray `amount` key in a schema 6 object is ignored.
  - **Migration schema 4 → 5** (remote mappings only, `a` = old amount, `r` = old range, each result clamped to 0..1; derived before the schema 6 fold): `+` min 0, max `a·r`; `−` min 1, max `1 − a·r`; `±` min `0.5 − a·r/2`, max `0.5 + a·r/2`. Exact (tables within 1e-9) unless a clamp bites, which needs a negative amount on `+` / `−` (the old output was clamped per sample, min / max clamp the endpoints, so e.g. `+` with amount < 0 becomes a constant 0, the same response). Mod mappings just gain min 0 / max 1. Schema < 4 goes through the migration below first (it yields `+`, range 1, amount 1, i.e. min 0 / max 1 with the old limits baked into the shape).
  - **Migration (schema < 4)**: the old affine parts are baked into the shape's point y values (an affine map of the y values affinely maps `evalMseg` for every bend and S-curve, since the segment easing does not depend on y). Mod: `y' = lo + (hi-lo) * (invert ? 1-y : y)` with `lo/hi = min/max` (schema 3) or `0/1` (schema < 3, where Mod ignored them), `polarity = bipolar ? 0 : 1`, range 1, amount unchanged. Remote: `y' = min + (max-min) * (invert ? 1-y : y)`, `polarity 1`, range 1, amount 1, so `v = y'`, the old value. Schema 1 curve fields go through `curveToShape` first. `tests/test_megamod.js` checks schema 1 / 2 / 3 × Mod / Remote × invert × bipolar × min/max (max table error about 2e-16). Raw objects without `polarity` handed straight to `mappingOutput` / `mappingTable` still use the legacy formula.
- **Schema 5 (superseded)**: Mod used `o = amount * range * (...)` with `amount` −1..1 (default 0.5, range default 1).
- **Schema 4 (superseded)**: Remote used polarity / range / amount (see the migration above).
- **Schema 3 (superseded)**: `min` / `max` were range markers in both modes (Schema < 3 Mod mappings, whose min/max were ignored, loaded the full range).
- **Schema 2**: each mapping carries `shape` (MSEG points `{x,y,curve,sCurve}`) instead of `curve` / `curveAmt` / `curveSteps`. **Migration**: a mapping without `shape` is converted by `curveToShape(curve, curveAmt, curveSteps)` in `sanitizeMapping`. Exp / Log / S with power up to `2^3.6` become one segment (exact, same power law), steeper ones 32 fitted segments, Stepped becomes hard steps (two points per step, `0.0001` apart at the edges). `tests/test_megamod.js` checks every old curve type against the legacy `shapeCurve` formula (max table error below 0.02). `shapeCurve` is kept only as that reference.

## 22. Architecture of `devices/Timbre Split.amxd`

A Rack-chain splitter like Multiband Split (section 11), but it splits by **timbre class** instead of frequency band. Put one instance per chain of an Audio Effect Rack. The linked instances share 2..4 learned classes (kick / snare / hat, voiced / unvoiced, ...). Each chain passes only its class, and the chains add up to the input, delayed by a constant **2048 samples** (`"latency": 2048`). Built on the Timbre Follower A look (section 20).

### Files
- `src/tsplit_core.genexpr`: the gen core (needs `src/cepstrum_lib.genexpr` prepended). `src/tsplit_ref.js` is its Node mirror (`TimbreSplitRef`, `TsplitChain`, `synthDrumLoop`, `renderChains`).
- `src/tsplit_config.js`: pure helpers, `require`d by the tests and concatenated in front of the UI: `classifyFrame`, `smoothKernel`, `resolveEffectiveClassMask`, `createKMeansLearner`, the state blob (`encodeStateBlob` / `decodeStateBlob`), `parseRackContextFromPath`, leader election.
- `src/tsplit_ui.js`: the v8ui (drawing, mouse, link engine, learning). `scripts/build_tsplit.py` builds `devices/Timbre Split.amxd`. `tests/test_tsplit.js` is the offline suite.
- `scripts/run_tsplit_audio_tests.py` + `tests/tsplit_probe.js` + `tests/tsplit_ref_cli.js`: the real-Max audio test (VM only).
- Typecheck: `tsconfig.tsplit.json`; `src/tsplit_ref.js` is in `tsconfig.refs.json`.

### DSP (`src/tsplit_core.genexpr`)
- **Analysis** is Timbre Follower's: N 1024, hop 256, mono mix, 24 mel bands, c1..c13 (class feature) and c0 (level feature, telemetry only). Gate -60 / -66 dB, idle sleep after 200 quiet hops.
- **Memberships.** Per hop: Euclidean distance `d_k` from c1..c13 to each of K centroids (`Buffer cent("tsplitcent")`, centroid k at `k * 16`), `p_k ~ exp(-beta * (d_k - d_min - bonus_k))`, normalised to sum 1. `beta = 0.1 * 40^(Sharp/100)`. `bonus` is **hysteresis**: the incumbent winner counts as 1.0 distance unit closer. A closed gate or idle device holds the last `p`.
- **Smoothing.** Each hop's `p` goes into a 16-hop ring; `S_{j-3}` is a normalised Gaussian (sigma = Smooth ms in hops) over hops `j-6 .. j`, so `S` always sums to 1.
- **Perfect reconstruction.** Per sample `g_k = lerp(S_{j-4}, S_{j-3}, phase / 256)`, `sum_k g_k = 1`. A chain outputs `delayed_input * sum_k g_k * m_k * gain`, where `m_k` are the one-pole smoothed (3 ms) bits of its class mask. Chains with disjoint masks covering all classes sum to the delayed input to 1 ulp (JS mirror: below -300 dB, test limit -120 dB).
- **Lookahead.** The audio is delayed 2048 samples (`Delay dl1/dl2(4096)`, `read(2048)`). `S_m` is applied 512 samples before its frame centre (anticipation = latency - 768 - 256 * 3), so an onset opens its class before the hit: the first 3 ms of every hit land > 95 % in its own chain, peaks lose < 0.75 dB at Sharp 60 and < 0.1 dB at Sharp 100.
- **Telemetry**: `buffer~ #0-tsplitscope @samps 2592`, bound `scope #0-tsplitscope`: header 0 hop counter (written last), 1 head, 2 gate, 3 sample rate, 4 level dB, 5 K, 6..9 class gains, 10 idle, 12 latency, 13 winner; columns at `32 + 20 j`: c1..c13, c0, p1..p4, winner (1-based, 0 = gated), gate. Centroids: `buffer~ #0-tsplitcent @samps 64`, bound `cent #0-tsplitcent`; an unbound buffer reads zeros, so every class distance ties and each chain gets `1/K` (still sums to 1).

### Controls (presentation `440 x 169`, v8ui `x = 8, y = 8, w = 270, h = 153`, nothing overlaps it)
- Visible: `Learn` (toggle), `Adapt` (toggle), `Classes` (2..4, Int), `Sharp` (0..100 %, default 60), `Smooth` (0..60 ms, default 8). Right panel `x = 282..434`.
- In the v8ui, like Multiband Split: `AUTO` pill, `CLASS 1..K` pills (click solos, shift-click or the right edge multi-selects) and the `Gain` slider (-inf..+18 dB, vertical drag, double-click resets). Hidden automatable parameters keep them in sync: `Chain Gain`, `Class Mode` (`Auto Chain`, `Class 1..4`, `Multi`), `Link Group`.
- v8ui layout: top strip; MFCC heatmap (c1..c13 x 128 columns, each column tinted by its winning class, a 1.6 px class tick on top); class-membership timeline (stacked weights, dim while the gate is closed); `CENTROIDS` fingerprint tiles (one per class, bright border = the classes this chain passes); learn bar (`FACTORY PRIOR - PRESS LEARN` / `LEARNING n%` / `LEARNED n CLASSES`); per-class gain meters; link badge (`LINK: RACK #1 CH2 (3x) LEAD`, click toggles `LNK`).

### Link engine (adapted from section 11)
- Same rack/chain scoping as Multiband Split: `parseRackContextFromPath`, `Global("tsplit_shared_bus")`, nested racks link only with their own siblings, a `Cmd+D` duplicate to the right in the same chain gets an isolated group, a cached `selfLiveApi`.
- **Auto class assignment** (`resolveEffectiveClassMask`): chain rank N passes class N. With fewer chains than classes the **last chain also passes every leftover class**; with more chains than classes the extra chains pass nothing. So Auto masks always partition the classes and the sum stays the input. Deleting a chain compacts the ranks.
- **Shared across the group (every gen must classify identically)**: `Classes`, `Sharp`, `Smooth`, `Adapt`, the centroids and the learn state. Per chain: class mode, custom mask, gain, link group.
- **Leader** = the first alive chain (lowest chain, device, creation order). Only the leader learns and adapts; any instance's `Learn` button is forwarded to it, and everyone mirrors its progress and `ui_learn`.
- **Learn**: starts an online k-means over the next 6 bars (tempo read through `LiveAPI("live_set")`, fallback 120 bpm), from the leader's own MFCC telemetry. Farthest-first seeding and MacQueen updates run per hop; the live estimate is refined by Lloyd on the reservoir and poked into every linked instance's `tsplitcent` about 4 times a second. Pressing `Learn` again stops early; at the end (or the stop) k-means++ restarts + Lloyd polish the take, classes are sorted by c1 (darkest = class 1) and the centroids **freeze**. A take with fewer than 40 frames is dropped. Changing `Classes` aborts a take.
- **Adapt**: the leader lets the centroids drift toward the incoming audio, weighted by each class's membership (rate 0.00015 per hop, a ~35 s time constant), and shares them every 0.5 s.
- **State**: `TsplitStateData` blob (`parameter_type: 3`), version 1, 63 numbers: `[1, classes, sharp, smooth, adapt, classMode, customMask, linkGroup, gainDb, showLinkStatus, learned, centroid[0][0..12] ... centroid[3][0..12]]`. Shorter arrays load the prefix and keep the rest, a future version parses the v1 prefix, NaN centroids are rejected. The `pattr` initial value is the 11-number prefix.
- Until the user learns, a factory prior (bass-, sine-, noise-, saw-like MFCCs) is used and the learn bar says so.
