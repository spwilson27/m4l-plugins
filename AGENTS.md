# AGENTS.md — Technical Guide & Rules for AI Contributors

This repository contains Max for Live (`.amxd`) devices for **Ableton Live 12 Suite (Max 9.1+)**.

---

## 1. Core Project Rules

1. **Directory Structure**:
   - **`devices/`** — Output directory for all compiled `.amxd` devices (e.g., `devices/Bitwig Shaper.amxd`). Never leave generated `.amxd` files in the project root.
   - **`src/`** — JavaScript (`v8ui` / `v8.codebox`) and DSP source files (e.g., `src/mseg_editor.js`).
   - **`scripts/`** — Build and visual preview scripts (`scripts/build_shaper.py`, `scripts/render_preview.py`).
   - **`tests/`** — Automated verification and unit/interaction test suites (e.g., `tests/test_shaper.js`).
   - **`previews/`** — Rendered 2x Retina plugin screenshots named per plugin (e.g., `previews/bitwig_shaper.png`).
2. **Never Hand-Edit `.amxd` Binary Files**:
   - `.amxd` files in `devices/` are build artifacts generated by `scripts/`. Always edit `src/` and `scripts/`, then run the build script to regenerate `devices/*.amxd`.
3. **Mandatory Build, Test & Visual Screenshot Inspection Gate**:
   - Every change to `src/` or `scripts/` **must** be followed by running the build, test, and preview pipeline for that plugin:
     ```bash
     # Bitwig Shaper
     python3 scripts/build_shaper.py && node tests/test_shaper.js && python3 scripts/render_preview.py "devices/Bitwig Shaper.amxd"

     # XO Sample Map
     python3 scripts/build_xo_map.py && node tests/test_xo_map.js && python3 scripts/render_preview.py "devices/XO Sample Map.amxd"

     # Tiny Space
     python3 scripts/build_tinyspace.py && node tests/test_tinyspace.js && python3 scripts/render_preview.py "devices/Tiny Space.amxd"
     ```
   - **Visual Screenshot Inspection**: After generating `previews/<plugin_slug>.png`, agents **must** view the image in `previews/` using the `read` tool and visually verify that:
     - No text labels or toolbar buttons are truncated, squished, or overlapping.
     - Compact toolbar buttons use clean geometric vector icons (`mgraphics` paths) rather than multi-character text strings when cell width is `< 28px`, displaying full titles in the HUD tooltip on hover.
     - All `live.*` widgets, panels, and `v8ui` canvases have balanced padding and alignment.
   - Any visual defect identified in the screenshot must be fixed and re-verified before finishing.
4. **Presentation Mode Layout & Z-Order Rules**:
   - Max for Live devices must maintain a fixed presentation height of **`169.0` px** (`openrect: [0.0, 0.0, <devicewidth>, 169.0]`, `openinpresentation: 1`).
   - **Never overlap `live.*` interactive widgets (`live.numbox`, `live.text`, `live.dial`, `live.tab`) with a `v8ui` / `jsui` canvas in Presentation Mode.** Max's `v8ui` captures all mouse clicks over its `presentation_rect`. Keep `live.*` widgets in non-overlapping header/side regions (verified automatically by `tests/test_shaper.js`).
5. **Instance Isolation (`#0-` Naming)**:
   - Any `buffer~`, `send`, or `receive` that belongs to a single device instance **must** be prefixed with `#0-` (e.g., `buffer~ #0-mseg`, `index~ #0-mseg`) so multiple instances of the device across an Ableton Live Set never collide.
6. **Backward-Compatible State Serialization (`getvalueof` / `setvalueof`)**:
   - `v8ui` state is saved in Ableton Live Sets (`.als`) and presets (`.adv`) via blob parameter `ShapeData` (`parameter_type: 3`).
   - Always version the array returned by `getvalueof()` (first element = version integer) and keep fallback parsing for earlier versions inside `setvalueof()` so existing Live Sets never lose user curves.
7. **Undo Stack Discipline**:
   - Any user interaction that mutates MSEG points, segment curves, S-curve flags, or loop markers must call `pushUndoState()` once at the start of the gesture (`onclick` or `ondblclick`)—never on every `ondrag` frame—and call `notifyclients()` on gesture completion.

## 2. `.amxd` Binary Format Reference

An unencrypted Max for Live `.amxd` file consists of a 32-byte binary header followed by UTF-8 JSON patcher data:
- Bytes `0..7`: `b"ampf\x04\x00\x00\x00"`
- Bytes `8..11`: Device type 4CC:
  - `b"aaaa"` (`amxdtype: 1633771873` / `0x61616161`) — Max Audio Effect (`plugin~` / `plugout~`)
  - `b"mmmm"` (`amxdtype: 1835887981` / `0x6d6d6d6d`) — Max MIDI Effect (`midiin` / `midiout`)
  - `b"iiii"` (`amxdtype: 1768515945` / `0x69696969`) — Max Instrument
- Bytes `12..23`: `b"meta\x04\x00\x00\x00\x00\x00\x00\x00"`
- Bytes `24..27`: `b"ptch"`
- Bytes `28..31`: `uint32_le` length of the following JSON byte payload.
- Bytes `32..end`: UTF-8 encoded patcher JSON ending with `\n`.

## 3. Architecture of `devices/Bitwig Shaper.amxd`

### Presentation Layout (`492 x 169` px — Native 2-Panel Footprint)
- **Left Panel (`x = 6..334`) — Toggles Between MSEG View & 8-Slot Mod View**:
  - **Top Row (`y = 8..23`, Always Visible)**:
    - Slot 1 (`Map[1]`, `Unmap[1]`, `ModMode[1]`, `Bipolar[1]` + `ModAmount[1]` or `TargetMin[1]` + `TargetMax[1]`) on the left, and the Multimap Show/Hide button (`obj-expand-map`, `multimap-closed-off.svg` / `multimap-open-off.svg` at `x = 311, y = 8`) on the top-right.
  - **MSEG View (`ShowModPanel == 0`, default)**:
    - MSEG Editor (`obj-mseg`, `v8ui`, `x = 10, y = 26, w = 318, h = 134`):
      - `y = 0..11`: Loop Start / End region bar.
      - `y = 18..106`: Main MSEG plot area (`7px` horizontal & top padding so `0%` and `100%` points never clip).
      - `y = 112..134`: 14-item vector icon toolbar on `x = 0..214`, with the right `104px` (`x = 225..324, y = 141..157`) hosting `Grid` (`obj-grid-lbl`, `obj-grid`) and `Snap` (`obj-snap-btn`).
  - **8-Slot Mod View (`ShowModPanel == 1`)**:
    - Hides `obj-mseg`, `obj-grid-lbl`, `obj-grid`, and `obj-snap-btn` (`hidden 1`).
    - Displays Slots 2–8 (`row_y = 8 + i * 16.5` via `p SlotVis_2..8`) and the bottom column labels (`Parameter`, `Mode`, `— Range —` at `y = 143`).
    - In each slot `1..8`, `ModMode == 0` (`Mod`, `live.modulate~`) shows `Bipolar` (`+` / `±`) and `ModAmount` (`-100%..+100%`), while `ModMode == 1` (`Remote`, `live.remote~ @normalized 1`) shows `TargetMin` (`0%..100%`) and `TargetMax` (`0%..100%`).
- **Right Panel (`x = 338..488` — Live 12 Native Shaper Layout)**:
  - Top dark LCD panel (`y = 5..82`):
    - `live.scope~` (`x = 340..486, y = 7..46`).
    - LCD Row 1 (`y = 47..63`): `Jitter` (`0 %`) and `Smooth` (`0 %`) borderless `live.numbox` controls (`appearance: 4`).
    - LCD Row 2 (`y = 63..79`): Circular `(R)` Retrigger button (`obj-retrig`), `Ø` Phase label + `Phase` (`0.00 %`) borderless `live.numbox`, and `Offset` (`0 %`) borderless `live.numbox`.
  - Middle playback mode row (`y = 88..103`): `[ Loop ] [ 1-Shot ] [ Manual ]` horizontal `live.tab` (`obj-play-mode`, driving `selector~ 2 1` between `phasor~`, one-shot `line~`, and manual `Ø` phase scrubbing).
  - Bottom controls (`y = 110..158`): `Rate` (`Hz` dial and `Sync` dial toggled via `hidden $1`), horizontal connecting line (`obj-rate-line`), stacked `Hz` / Metronome `live.tab` (`obj-rate-mode`), and `Depth` dial.

### `v8ui` + Audio-Rate `buffer~` Integration
- `obj-mseg` (`maxclass: "v8ui"`) embeds the ES6+ script inline via `"textfile": { "text": ..., "filename": "none", "flags": 0, "embed": 1, "autowatch": 1 }`.
- `obj-buf` (`buffer~ #0-mseg @samps 4096`) holds the 4096-sample lookup table. On startup, `loadmess setbuffer #0-mseg` passes the unique `#0-mseg` buffer name to `v8ui`, which writes all 4096 samples via `new Buffer(bufName).poke(1, 0, samples)` whenever the curve changes.
- `v8ui` Outlet 0 emits `["loop", loopStart, loopSpan]` to window the MSP `phasor~` phase into `[loopStart, loopStart + loopSpan]`, and `["syncphase", phase]` to align `phasor~` with Ableton Live's 1-PPQ arrangement timeline position (`plugsync~` outlet 6) in Sync mode.
- `v8ui` Outlet 1 emits the LFO frequency in Hz to `phasor~` (automatically scaled by `1 / loopSpan` when a loop sub-region is active so tempo-synced subdivisions keep constant musical speed).

## 4. Architecture of `devices/XO Sample Map.amxd`

### Presentation Layout (`680 x 169` px)
- **Left Panel (`x = 6..386`)**:
  - Top bar (`y = 8..24`): Device Title (`XO Sample Map`), `Open Map` toggle (`live.text`), `Scan Core` (`live.text`), `+ Folder` (`live.text` -> `opendialog fold`), and `+ Save (S)` (`live.text`, saves current sample + playback settings to the Saved List).
  - Mini Editor (`obj-minimap`, `v8ui`, `x = 10, y = 27, w = 372, h = 134`):
    - **Left Pane (`x = 0..244`)**:
      - `y = 0..20`: Selected sample badge, name, and 24-bar decay-scaled waveform viewer with a **live scanning playhead line (`set_playhead`)** driven by `line 0. 20`.
      - `y = 22..112`: Interactive 2D sample constellation map with k-NN neighbor lines and filter-aware drag-to-scrub auditioning.
      - `y = 112..134`: 12-item geometric vector icon toolbar (`All`, `Kick`, `Snare`, `Hihat`, `Clap`, `Tom`, `Cymbal`, `Perc`, `FX`, `Prev Similar`, `Next Similar`, `Random`).
    - **Right Pane (`x = 236..372`) — Scrollable Saved Samples List & OS File Drag-Out Dock**:
      - `y = 0..20`: `SAVED (N)` header, `+Save` button (`S` hotkey), and `×` clear-all button.
      - `y = 21..109`: Scrollable window of saved sample rows (with right-edge scrollbar thumb) supporting click-to-select/recall, vertical drag-to-reorder (`reorder_saved`), per-row `[×]` delete button (`Delete`/`Backspace` key), and separate per-item **`[R]` (Raw)** and **`[E]` (Edited)** OS file drag handles.
      - `y = 112..134`: Bottom batch OS file drag-out zones **`[Drag Raw]`** (`all_raw`) and **`[Drag Edit]`** (`all_edited`).
- **Center Panel — `FILTERS` (`x = 392..530`)**:
  - Visibly separate cyan-bordered panel containing `Search:` label, `Clr` button, `obj-search-box` (`textedit` for filtering by name), `MaxLen` (`50 ms` up to **Infinite / `Inf`** at max) and `Tone` (`%`) dials, and `< Sim`, `Sim >`, `Rand` buttons.
- **Right Panel — `PLAYBACK` (`x = 536..674`)**:
  - Visibly separate amber-bordered panel containing `Audition / Replay`, `Pitch` (`st`), `Trim/Dec` (`ms`), and `Gain` (`dB`).

### Multi-Engine Integration (`node.codebox` + `jweb` + `v8ui` + Native Cocoa Drag Helper)
- `obj-node` (`node.codebox`) embeds both `src/xo_map_ui.html` (`EMBEDDED_XO_HTML`) and `src/xo_node_engine.js` so `devices/XO Sample Map.amxd` is a single self-contained `.amxd` file.
- `obj-sfplay` (`sfplay~ 2`) routes outlet 0 (Left/Mono) to both the Left multiplier and `obj-r-chan-sel` (`selector~ 2 1`) inlet 1, while outlet 1 (Stereo R) feeds `selector~ 2 1` inlet 2. `node.codebox` emits `play_mono 1` for 1-channel files and `play_mono 2` for stereo files, ensuring mono samples play on both channels.
- When samples are saved (`save_selected` / hotkey `S`), `xo_node_engine.js` creates an OS file link in `/tmp/xo_sample_map_exports/Raw/` and a 2-channel stereo 16-bit PCM re-rendered WAV file in `/tmp/xo_sample_map_exports/Edited/`, and arms a compiled macOS Cocoa `NSDraggingSource` helper (`xo_drag_helper`) so dragging out of `[R]`, `[E]`, `[Drag Raw]`, or `[Drag Edit]` performs a true OS file drag into Ableton Live.

## 5. Architecture of `devices/Tiny Space.amxd`

### Presentation Layout (`660 x 169` px)
- **Left Panel (`x = 6..406`)**:
  - Top bar (`y = 7..24`): Title (`Tiny Space`), plus `Seed` (`live.numbox`, 0–9999) and `Freeze` (`live.text`) in the right of the bar.
  - Visualization canvas (`obj-viz`, `v8ui`, `x = 10, y = 27, w = 396, h = 134`): 20 per-delay-line energy bars (left 10 cyan, right 10 amber) with decay trails; readout of seed + active line count.
- **Right Panel (`x = 410..654`)**:
  - 12 dials in a 4×3 grid (`Size`, `Damp`, `Width`, `Mix`, `Feedback`, `PreDly`, `Mod`, `XFeed`, `InGain`, `OutGain`, `HP`, `LP`), each `live.dial` 44×48.

### Gen core (`gen.codebox~`, hidden)
- `src/tinyspace_core.genexpr` — FDN reverb: input gain → HP/LP → input allpass diffusion → 20 delay lines (10 L / 10 R) with fractional (linear-interpolated) read, per-line one-pole damping, per-line feedback, modulation, crossfeed → width (M/S) → dry/wet → output gain.
- `in1`/`in2` = audio L/R; `in3..in15` = controls (size, damp, width, mix, feedback, freeze, predelay, ingain, outgain, hp, lp, mod, crossfeed); `out1`/`out2` = audio; `out3..out22` = per-line meters.
- `Buffer cfg(\`#0-tsconfig\`)` reads the seed-driven config: `[activeCount, len0..19, char0..19]`.

### Seed → config
- `src/tinyspace_ui.js` runs a seeded PRNG (mulberry32) from the `Seed` numbox and pokes the 41-float config into `buffer~ #0-tsconfig`. Internals only — user controls stay manual.
- `getvalueof()`/`setvalueof()` versioned (v1): `[1, seed]`.

### Audio validation
- `tests/tinyspace_harness.maxpat` embeds the same gen core plus extra audio in/out sinks (test tone → gen → capture buffer) for automated audio checks.
- `scripts/run_tinyspace_audio_tests.py` launches Max with the harness.

### Build / Test / Preview
```bash
python3 scripts/build_tinyspace.py && node tests/test_tinyspace.js && python3 scripts/render_preview.py "devices/Tiny Space.amxd"
```
